# Spec: Companion services (library, speech-to-text, text-to-speech, maps, vision)

> **Status:** approved design · **Epic:** E4 · **Code:** `agent/internal/svc/kiwix/`, `agent/internal/svc/whisper/`, `agent/internal/svc/piper/`, `agent/internal/maps/`, `agent/internal/svc/health/`, `agent/ui/src/maps/` · **Doctor area:** `LAI-SVC` (codes 001–099; 100–149 belong to [survival-portal.md](survival-portal.md))
> Canonical names: [overview.md](../architecture/overview.md) §3. Content comes from [ark-sync.md](ark-sync.md) (BestCopy). Router presets: [llama-router.md](llama-router.md). API routes: [agent.md](agent.md) §3.8.

---

## 1. Purpose and scope

Everything besides the LLM that a node needs to be useful offline: an offline library (Kiwix), speech-to-text (whisper.cpp), text-to-speech (Piper), offline maps, and image understanding (a vision LLM served by the router). This spec defines how each is installed, configured from the catalog, started, health-checked and exposed through the agent.

In scope:
- `localai-kiwix.service`: kiwix-serve, the merged library, the `/library/` proxy.
- `localai-whisper.service`: whisper.cpp build per backend, model selection, `POST /api/v1/speech/stt`.
- Piper: binary and voices, per-request exec, `POST /api/v1/speech/tts`, language selection.
- Maps: the MapLibre viewer, pmtiles range serving, local style/glyphs/sprites, offline place search, "where am I".
- Vision: the requirements on the router preset and the photo request format.
- Health checks and how they are surfaced.

Non-goals:
- Building a chat UI. The llama WebUI (`/chat/`) and the Portal's small screens ([survival-portal.md](survival-portal.md)) are the UIs.
- Routing or turn-by-turn navigation on the map. The viewer shows where things are; it doesn't plan routes.
- Online map tiles, online geocoding, or the browser Geolocation API (which in Chromium asks a network service). None are used, ever.
- Voice cloning, wake words, always-listening microphones.
- Translating Kiwix content.

## 2. Concepts

| Term | Meaning |
|---|---|
| **Merged library** | `/var/lib/localai/kiwix/library.xml`: one Kiwix library listing the best copy of every verified ZIM across all mounted content roots |
| **Per-root library** | `<root>/kiwix/library.xml`: lists only that root's ZIMs with relative paths, so a drive can be served by kiwix-serve on any machine |
| **Voice** | A Piper model: `<voice>.onnx` + `<voice>.onnx.json`, one catalog model with `engine: piper` |
| **Map** | One verified `pmtiles` file (`maps/<content-id>/*.pmtiles`) |
| **Map assets** | `maps/assets/` from the `map-assets` item: `fonts/<fontstack>/<range>.pbf` and `sprites/v4/<flavor>{.json,.png,@2x.json,@2x.png}` |
| **Place index** | An in-memory search index built from the GeoNames per-country dumps (item `places-central-america`) |

## 3. Interfaces

### 3.1 node.yaml keys owned by this spec

`node.yaml` is defined in [agent.md](agent.md) §3.4. agent.md must include these blocks.

```yaml
kiwix:
  enabled: true
  threads: 4                     # kiwix-serve --threads
whisper:
  enabled: true
  commit: "<40-hex whisper.cpp commit>"   # pinned; the kit tarball must exist for it (rebuild-kit.md)
  backend: auto                  # auto | cuda | vulkan | cpu   (auto = same as llama backend)
  device: auto                   # auto | gpu | cpu   (§4.2.3)
  model: auto                    # auto | <catalog whisper model id>
  threads: auto                  # auto = min(8, physical cores / 2)
  max_audio_seconds: 120
piper:
  enabled: true
  version: "2023.11.14-2"
  length_scale: 1.05             # >1 = slower, clearer speech
  default_voice: {en: auto, es: auto}     # auto = first voice for that language in the profile include list
maps:
  enabled: true
  default_map: auto              # auto = the tier-1 map in the profile; else a content id
  gps: auto                      # auto | off | gpsd | nmea:/dev/ttyACM0
  default_center: {lat: 9.93, lon: -84.08, zoom: 8}   # used when nothing else is known
```

The `piper` block is validated when node.yaml loads (`piper.BlockValidator`, a `config.Hooks.Blocks["piper"]`): unknown keys, a `version` that is not a release number, a `length_scale` outside 0.3 to 3.0 and a `default_voice` that is neither `auto` nor a plain id are errors (the last valid node.yaml stays in use).

### 3.3 systemd units

`/etc/systemd/system/localai-kiwix.service`:
```ini
[Unit]
Description=Local AI library (kiwix-serve)
Documentation=https://github.com/marinoscar/local-ai/blob/main/docs/specs/companion-services.md
After=local-fs.target
ConditionPathExists=/var/lib/localai/kiwix/library.xml
ConditionPathExists=/opt/localai/kiwix-tools/current/kiwix-serve

[Service]
Type=simple
User=localai
Group=localai
ExecStart=/opt/localai/kiwix-tools/current/kiwix-serve \
  --address=127.0.0.1 --port=8888 \
  --urlRootLocation=/library \
  --monitorLibrary --skipInvalid --blockexternal \
  --threads=4 \
  --library /var/lib/localai/kiwix/library.xml
Restart=on-failure
RestartSec=5
NoNewPrivileges=yes
PrivateTmp=yes
PrivateDevices=yes
ProtectSystem=strict
ProtectHome=yes
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectControlGroups=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK
RestrictNamespaces=yes
LockPersonality=yes
MemoryDenyWriteExecute=yes
SystemCallArchitectures=native
ReadOnlyPaths=/

[Install]
WantedBy=multi-user.target
```
The agent rewrites `--threads` from `kiwix.threads` when it writes the unit (the installer and `aiagent setup units` use the same template: `kiwix.RenderUnit` and `kiwix.WriteUnit` in `agent/internal/svc/kiwix`; `threads: 4` is the golden file `testdata/localai-kiwix.service.golden`, which is this text byte for byte, and a test fails if the two drift). `kiwix.threads` of 0 or absent means 4; the accepted range is 1 to 64 (outside it is `LAI-AGT-002`). The unit is written atomically (root 0644) and followed by `daemon-reload`; the writer never starts, stops, restarts or enables it. Drive content under `/media/…` is readable because `ProtectHome` covers only `/home`, `/root` and `/run/user`.

`/etc/systemd/system/localai-whisper.service`:
```ini
[Unit]
Description=Local AI speech-to-text (whisper.cpp server)
Documentation=https://github.com/marinoscar/local-ai/blob/main/docs/specs/companion-services.md
After=local-fs.target
ConditionPathExists=/etc/localai/whisper.env
ConditionPathExists=/opt/localai/whisper.cpp/current/bin/whisper-server

[Service]
Type=simple
User=localai
Group=localai
SupplementaryGroups=video render
EnvironmentFile=/etc/localai/whisper.env
ExecStart=/opt/localai/whisper.cpp/current/bin/whisper-server \
  --host 127.0.0.1 --port 8081 \
  --model ${WHISPER_MODEL} \
  --threads ${WHISPER_THREADS} \
  --language auto \
  $WHISPER_DEVICE_ARGS
WorkingDirectory=/var/lib/localai
Restart=on-failure
RestartSec=5
LimitMEMLOCK=infinity
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
LockPersonality=yes
SystemCallArchitectures=native

[Install]
WantedBy=multi-user.target
```
`$WHISPER_DEVICE_ARGS` is unbraced on purpose: systemd splits it into words, and an empty value adds no argument. `PrivateDevices` is **not** set, because the GPU device nodes are needed. Nothing in the unit varies (the model, the threads and the device arguments come from `whisper.env`), so `whisper.RenderUnit` and `whisper.WriteUnit` in `agent/internal/svc/whisper` write exactly this text: `testdata/localai-whisper.service.golden` is it byte for byte, and a test fails if the golden file and this block drift. The unit is written atomically (root 0644) and followed by `daemon-reload`; the writer never starts, stops, restarts or enables it. CI runs `systemd-analyze verify` on the golden file (`scripts/verify-units.sh`).

Piper has no unit. It is exec'd per request by the agent (§4.3).

Both units are `enabled` by the installer. The agent starts, stops and restarts them through systemd D-Bus (`org.freedesktop.systemd1`), never by spawning `systemctl` with a shell.

### 3.4 HTTP: speech (routes fixed in agent.md)

**`POST /api/v1/speech/stt`** (auth: bearer, session, or a Portal-scope session in survival mode, see [survival-portal.md](survival-portal.md) §3.3). `multipart/form-data`:
| Field | Required | Notes |
|---|---|---|
| `audio` | yes | `audio/wav` (RIFF, PCM 16-bit or 32-bit float, any rate, 1–2 channels). ≤ 25 MiB and ≤ `whisper.max_audio_seconds` |
| `language` | no | `auto` (default), `en`, `es`, or any whisper language code |
| `prompt` | no | ≤ 200 chars, passed as whisper's initial prompt (e.g. names) |

Response `200`:
```json
{"text": "How do I clean a deep cut?", "language": "en", "language_probability": 0.97, "duration_s": 3.2, "model": "whisper-small", "elapsed_ms": 1840}
```
Errors (all JSON `{code, title, fix}`, see agent.md error shape):
| Status | Code | When |
|---|---|---|
| 400 | `LAI-SVC-014` | not WAV, unsupported encoding, too long, empty, or silent (RMS below −60 dBFS) |
| 413 | `LAI-SVC-014` | larger than 25 MiB |
| 429 | `LAI-SVC-015` | 2 requests already queued |
| 503 | `LAI-SVC-010` / `011` | no model / server down |
| 504 | `LAI-SVC-016` | whisper took longer than 60 s |

**`POST /api/v1/speech/tts`** (same auth). JSON:
```json
{"text": "Press firmly on the wound with a clean cloth.", "voice": null, "language": "en", "speed": 1.0}
```
- `text`: 1–2000 chars after cleanup (§4.3.3). Longer → `413 LAI-SVC-024` (callers split by sentence).
- `voice`: a catalog piper model id, optional.
- `language`: `en`, `es`, or `auto` (default).
- `speed`: 0.7–1.5, multiplies `piper.length_scale` inversely.

Response `200`, `Content-Type: audio/wav`, headers `X-LocalAI-Voice: piper-en-medium`, `X-LocalAI-Language: en`, `X-LocalAI-Fallback: true` when the requested language had no voice. Errors: `400 LAI-AGT-020` (malformed body, unknown `voice`, `language` not `auto|en|es`, `speed` outside 0.7 to 1.5, empty text after cleanup), `503 LAI-SVC-022` (no voice, or `piper.enabled: false`), `503 LAI-SVC-020` (the program is not installed), `500 LAI-SVC-023` (piper failed), `429 LAI-SVC-015` with `Retry-After` (more than 2 concurrent syntheses + 4 queued). The Portal sends its language in `X-LocalAI-UI-Language` (rule 4 of §4.3.4).

**`GET /api/v1/speech/voices`** (agent.md §3.8.25; auth `op` or `portal`; 5 s): `{"voices":[{"id":"piper-en-medium","language":"en","display_name":"English (US), medium","default":true}]}`. Needed by the Portal to show the voice picker.

### 3.5 HTTP: library and maps (non-API agent paths)

These live outside `/api/v1`. They are in the unauthenticated survival set (security-model.md §3) and are loopback-only like everything else. They accept only `GET` and `HEAD`, except `PUT/DELETE /maps/whereami` (same-origin check required).

| Path | Behaviour |
|---|---|
| `/library/…` | Reverse proxy to `http://127.0.0.1:8888/library/…` (path preserved, because kiwix-serve runs with `--urlRootLocation=/library`). Hop-by-hop headers removed; `X-Forwarded-*` not added. `503` with a bilingual HTML page "The library is not running" + `LAI-SVC-002` if the upstream is down (a per-mount exception to the generic `502` of [agent.md](agent.md) §3.11). Response timeout 600 s |
| `/maps/` | The viewer (embedded SPA) |
| `/maps/catalog.json` | Available maps and assets (§4.4.2) |
| `/maps/tiles/<content-id>.pmtiles` | The best copy of that map, with HTTP Range (§4.4.1) |
| `/maps/assets/<path>` | Files under the best copy of `maps/assets/` |
| `/maps/search?q=&near=<lat>,<lon>&limit=20&lang=en` | Place search (§4.4.4) |
| `/maps/nearest?lat=&lon=&kind=<kind>&limit=5` | Nearest places of a kind (§4.4.4) |
| `/maps/whereami` | `GET` current position; `PUT {lat, lon, label?}` set manually; `DELETE` clear (§4.4.5) |

## 4. Behaviour

### 4.1 kiwix-serve

#### 4.1.1 Binary
- Source: the official static release tarball `kiwix-tools_linux-x86_64-<ver>.tar.gz` (or `linux-aarch64`) from `https://download.kiwix.org/release/kiwix-tools/`. It is a catalog `kit` item (`kit-kiwix-tools`, source `url`, pinned sha256), so the same tarball is in `kit/tools/kiwix-tools/` ([rebuild-kit.md](rebuild-kit.md) §Contents).
- Install (installer, and `aictl kit install kiwix-tools`; code: `agent/internal/svc/kiwix`, `kiwix.Install(ctx, tarball, expectSHA256, version)`): works offline on the kit tarball, in this order.
  1. Refuse a `version` that is not a release number (`3.7.0-2`), a pin that is not 64 hex characters (an unverified tarball is never installed), and a release file of the other architecture (`runtime.GOARCH` `amd64` is `x86_64`, `arm64` is `aarch64`; helpers `kiwix.TarballName` and `kiwix.KitPath` build the kit file name and path).
  2. Verify the tarball sha256 against the pin from the kit MANIFEST (catalog `kit-kiwix-tools`). A mismatch changes nothing on disk.
  3. Extract to `/opt/localai/kiwix-tools/<ver>.tmp/` (a leftover from a killed run is removed first), dropping the one top directory the release unpacks into, so the files are `<ver>/kiwix-serve`, `kiwix-manage`, `kiwix-search`. Every entry is checked before it is written: no absolute path, no `..`, no backslash, no hard link, device or other special file, no duplicate, and a symlink only when its target is a plain sibling name in the same directory (anything with a `/`, `.` or `..` could be chained out of the target); nothing is written through a symlink; at most 1000 entries and 512 MiB. The three programs get `chmod 0755` whatever the archive says. The last file written is `.tarball.sha256` (the pin), which marks the directory complete.
  4. Smoke test the new directory in place (`<ver>.tmp/kiwix-serve --version`, through `execx`) before it is moved to `/opt/localai/kiwix-tools/<ver>/`, so a binary that cannot run never replaces a working one. A `<ver>/` that already holds this very tarball (same `.tarball.sha256`, three executable files) is reused and only smoke tested; a different or damaged `<ver>/` is replaced.
  5. Atomically repoint `current` (`ln -sfn <ver> current.tmp && mv -T current.tmp current`, in Go a symlink `current.tmp` and a rename). Other version directories are kept; a `current` that is not a symlink is never replaced.
  Any failure removes the temporary directory and leaves `current` as it was. Every failure carries `LAI-SVC-003` (the library program is not (properly) installed; fix: `sudo install-node.sh --repair`).
- Check (`kiwix.Check(ctx, version)`): `/opt/localai/kiwix-tools/current/kiwix-serve --version` must print the expected version. The release prints `kiwix-tools <upstream version>` as its first line (no packaging revision), so `3.7.0-2` in the file name is satisfied by `3.7.0` or `3.7.0-2`. A missing program, a program that does not run or exits non-zero, and a different version all fail with `LAI-SVC-003`.
- Doctor: the fast check `svc.kiwix_installed` (`Installer.DoctorCheck`, registered by the agent only while `kiwix.enabled` is true) raises `LAI-SVC-003` when `/opt/localai/kiwix-tools/current/kiwix-serve` is missing.
- The flags used in §3.3 are checked against the usage text of the pinned release: for kiwix-tools 3.8.2 (`src/server/kiwix-serve.cpp`, docopt) `--address`, `--port`, `--urlRootLocation`, `--monitorLibrary`, `--skipInvalid`, `--blockexternal` and `--threads` are all long options, and the library is the positional argument of `(-l | --library) LIBRARYPATH` (written `--library <path>`, never `--library=<path>`). The issue that pins a new version repeats the check with `kiwix-serve --help` on a node (manual test of SVC-02).

#### 4.1.2 Library regeneration
Triggered on agent start, on `sync.item_done` for a kiwix item, on `drive.mounted` / `drive.unmounted`, and on `aictl services restart kiwix`. Debounced: at most once per 10 s.
1. For each catalog kiwix item, get `ark.BestCopy(id)`. Skip items without a verified copy. On an `unclean` drive, wait for the serve-time verification ([ark-sync.md](ark-sync.md) §4.1.3).
2. If two items have the same ZIM `Name` metadata (possible across catalog revisions), keep the one with the newest date.
3. Build into a temp file in the same directory: `kiwix-manage /var/lib/localai/kiwix/library.xml.tmp add <zim1> <zim2> …` (absolute paths), run as `localai`, timeout 120 s. Exit ≠ 0 → `LAI-SVC-005`, keep the old library.
4. Validate: the temp file parses as XML and has one `<book>` per ZIM added.
5. `rename` the temp file over `library.xml`. kiwix-serve, started with `--monitorLibrary`, reloads it within a few seconds.
6. If the library is now empty: stop `localai-kiwix`, set the service state `missing_content`, raise `LAI-SVC-001`. If it was empty before and isn't now: start the unit.
7. Ejecting or a surprise removal: after the rename, wait 10 s, then check `/proc/<kiwix pid>/fd` for files under the removed mount. If any remain, restart `localai-kiwix` (kiwix-serve may hold old ZIMs open after a reload).

Per-root libraries are regenerated the same way, but with `cwd=<root>/kiwix` and relative paths (`<id>/<file>.zim`), and only for that root's ZIMs, after every kiwix swap on a writable root.

*Implementation (SVC-03, `internal/svc/kiwix/library.go`, `service.go`, wired in `internal/app/kiwix_library.go`):*
- `Library.Regenerate` builds the merged library and `Library.RegenerateRoot(rootID)` a per-root one. The ZIM name of step 2 is the MANIFEST `source.book` (no ZIM parsing); the newest `sort_key` wins. Only the best copy of each kiwix item on a mounted root is listed, and a file that is no longer on disk (a drive pulled mid-run) is left out.
- `kiwix-manage` is run through `execx` as `localai` (cleared environment, 120 s, output capped) and always writes into `/var/lib/localai/kiwix/`. The agent validates the output (parses, one `<book>` per ZIM) and then writes the final file itself with the atomic write (0644, owner `localai`), so `kiwix-manage` never needs to write on a drive. A per-root library is that same output with the root's `<root>/kiwix/` prefix cut from every `path`, written atomically to `<root>/kiwix/library.xml`; read-only roots and roots without kiwix books are not written. The state directory is created with `internal/fsperm.MkdirAll` (0755) whatever the umask.
- If the batch fails and there are several ZIMs, each is tried alone: a damaged ZIM is skipped (logged with `LAI-SVC-004`) and the others are kept. If nothing usable is left, or `kiwix-manage` is missing, the old file stays and `LAI-SVC-005` is raised (cleared by the next good run). With no ZIM at all an empty library is written, `kiwix-manage` is not run and `LAI-SVC-001` is raised (cleared when a book appears). An unchanged set of ZIMs (paths and sizes) does not run `kiwix-manage` again.
- Triggers: agent start (after the ark stack and the drive detector are up), `sync.item_done` with result `verified`, `sync.done`, `drive.mounted`, `drive.unmounted`. They are coalesced: the first runs after a 2 s settle (so the best-copy index has been rebuilt by the drive and sync handlers), at least 10 s pass between two run starts, and a trigger arriving during a run causes exactly one more run (five triggers in 10 s give at most two runs). The loop only runs while `kiwix.enabled` is true.
- Unit control (`Service.Once`, `internal/svc/kiwix/service.go`, over the `Units` seam that the systemd `Manager` fills): an empty merged library stops `localai-kiwix` if it is running (the health probe then reports `missing_content` with `LAI-SVC-001`, because `Status.Content` says nothing is left to serve); books after an empty library, or on the first run after the agent started, start the unit if it is `inactive`. A unit that is `failed` is the supervisor's (restart budget), and a unit the operator stopped while books exist is left alone. A failed rebuild (`LAI-SVC-005`) never touches the unit.
- Step 7: `drive.unmounted` calls `Service.Removed(root)`. The service remembers the path of every root from its earlier runs, so it knows what was mounted where after the mount is gone. After the next run it waits 10 s, reads `MainPID` from `Manager.State`, lists `/proc/<pid>/fd` (`ProcFD`, a seam) and restarts the unit if a link points at or under a removed root (a ` (deleted)` suffix counts).
- `aictl services restart kiwix` (and `start`) goes through `POST /services/kiwix/{action}`; the `api.ServiceActions` wrapper in `internal/app/kiwix_library.go` triggers a regeneration after a successful one.
- Health hooks (`Status.Attach` fills the kiwix `health.FuncProbe`): `Content` is `missing_content` once a run found no books; `Readiness` reports `detail` "N books", `books[]` and compares `totalResults` of `GET /library/catalog/v2/entries?count=1` with the number of books in the merged library (mismatch is `degraded`, `LAI-SVC-004`; an unreadable catalog is no finding). The deep check (full-text search per tier-1 book) is not part of SVC-03.

#### 4.1.3 Article URLs
kiwix-serve exposes each book under its name with the date (`wikipedia_en_all_nopic_2026-10`) and, because date aliases are on by default, also without the date (`wikipedia_en_all_nopic`). Everything that links into the library (Portal first-aid links, the drill) uses the **undated alias**: `/library/content/<book-name-without-date>/<article-path>`. These links keep working across ZIM updates.

The agent exposes the mapping content id → book name in `GET /api/v1/services` (`kiwix.books[]`), so the Portal never hard-codes dates.

*Implementation (SVC-04, `internal/svc/kiwix/proxy.go`, `books.go`, mounted in `internal/app/build.go`):*
- `kiwix.NewProxy` is `proxy.New` with the target `http://127.0.0.1:<ports.kiwix>`, `StripPrefix` empty (path and query unchanged), `MethodPolicy: proxy.ReadOnly`, `DownStatus` 503 with `LAI-SVC-002`, the default 600 s timeout and no `X-Forwarded-*` (the helper removes the client's and adds none). `kiwix.Routes` registers it as one `GET` route (level none, no route deadline): a `POST` is `405` from the server and never reaches kiwix-serve; `HEAD` is served by the `GET` route.
- The CSP of §6 and `X-Content-Type-Options: nosniff` are set through the helper's `ResponseHook` when the upstream `Content-Type` starts with `text/html` (case-insensitive); every other type is passed through untouched.
- The 503 page is the shared error page, so its texts are those of `LAI-SVC-002` in `doctor-codes.md` ("The library service isn't running" / "El servicio de la biblioteca no se está ejecutando", with the fix in the same language). Language: the `X-LocalAI-UI-Language` header (`en` or `es`), else `Accept-Language` by q-value, else what the server resolved from `ui.language`.
- `books[]` is `kiwix.BookMap`: one element per book of the merged library of SVC-03 (`content_id` = the catalog item id, `name` = `source.book` with a trailing `_YYYY-MM` removed by `kiwix.UndatedName` (`^(.*)_\d{4}-\d{2}$`), `root` = the root of the chosen copy). It is filled by the kiwix readiness hook, so it is present while the unit answers.
- The Playwright test of the issue (`agent/ui/e2e/library-offline.spec.ts`) needs the `agent/ui` project, which does not exist in the tree yet; `TestProxyCSPOnHTMLOnly` proves the header, and the browser-side proof stays a manual check (see §9.3).

### 4.2 whisper.cpp server

#### 4.2.1 Build per backend
whisper.cpp is built from the pinned commit (`whisper.commit`) using the kit tarball `kit/src/whisper.cpp-<commit>.tar.gz` (online or offline; the tarball is always used, so online and offline builds are identical). Builder: the same code path as `aictl rebuild-llama` ([rebuild-kit.md](rebuild-kit.md) §rebuild-llama), exposed as `aictl rebuild-whisper` ([aictl.md](aictl.md) §4.23a). Ownership: SVC-05 owns this build target, the smoke test, the unit and the `aictl rebuild-whisper` command with `--commit`, `--backend`, `--source`, `--from-kit`, `--activate|--no-activate`, `--dry-run` and `--yes` (the engine of KIT-04 already carries `--from-kit` and `--dry-run`, so they are not held back); KIT-05 ([rebuild-kit.md](rebuild-kit.md) §10) adds `--prebuilt` and the export of whisper builds.

```
src=/var/lib/localai/build/whisper.cpp-<commit>
tar -xzf kit/src/whisper.cpp-<commit>.tar.gz -C /var/lib/localai/build/
cmake -S $src -B $src/build-<backend> -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_SHARED_LIBS=OFF \
  -DWHISPER_BUILD_EXAMPLES=ON -DWHISPER_BUILD_TESTS=OFF -DWHISPER_SDL2=OFF \

  <backend flags>
cmake --build $src/build-<backend> --target whisper-server whisper-cli -j <jobs>
```
| Backend | Flags |
|---|---|
| `cuda` | `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=<cc>` where `<cc>` is the GPU compute capability without the dot (`75` for the RTX 2070, `89` for the RTX 4080), from `nvidia-smi --query-gpu=compute_cap --format=csv,noheader` |
| `vulkan` | `-DGGML_VULKAN=ON` |
| `cpu` | none (OpenBLAS is not used, to keep dependencies minimal) |

`BUILD_SHARED_LIBS=OFF` gives a self-contained `whisper-server` (only system libraries such as libcudart, libvulkan and libc are dynamic), so it can be copied into `/opt` without rpath problems. Install: `/opt/localai/whisper.cpp/builds/<commit[:9]>-<backend>/bin/{whisper-server,whisper-cli}`, then repoint `current` atomically. Smoke test before repointing: `whisper-cli -m <model> -f <bundled en.wav> -l en -nt` exits 0 and prints non-empty text. If no whisper model has a verified copy yet (fresh node), the transcription step is skipped with a warning in the build output and `whisper-cli --help` exiting 0 is the smoke test (as rebuild-kit.md §4.3.3 does for llama). Keep the last 2 builds: the active one and the one it replaced (the rollback target), never the active one deleted.

`backend: auto` uses the llama backend from `node.yaml`. A node can force `cpu` (e.g. to keep all VRAM for the LLM, §4.2.3).

**What the code does (SVC-05).** There is one builder: `internal/router/build`'s `Manager` with `WhisperRecipe` (the llama build is `LlamaRecipe`; the recipe carries the flags, the targets, the programs, the root, the service and unit, the doctor codes, the audit action and the smoke test; everything else is shared, rebuild-kit.md §4.3.2 "What the code does (KIT-04)").
- **Layout.** Builds under `/opt/localai/whisper.cpp/builds/<commit9>-<backend>` with `current`, a build lock of its own. The source chain is the kit tarball, then the kit mirror of every root, then (online only) the GitHub clone; `--from-kit` takes the kit alone and `--source <dir>` a folder.

The backend is `--backend`, else `whisper.backend`; `auto` (also an absent key) is `llama.backend`, so `--backend auto` follows the llama backend even when `whisper.backend` says otherwise, and `--backend cpu` forces the processor. The CUDA architecture is `llama.cuda_arch`, else the compute capability of `nvidia-smi` (`7.5` becomes `75`; two cards `75;89`), else `LAI-HW-019`.
- **Preflight.** Every build, not only `--from-kit`, runs the offline preflight of [rebuild-kit.md](rebuild-kit.md) §4.3.1 (a missing tool is `LAI-KIT-010` with the `aictl kit install-debs` command, never `apt install`); `--dry-run` prints each check and exits 0 only if all pass.

The model is the smallest verified whisper model of the content roots (`models/<id>/MANIFEST.json`, engine `whisper`); the sample is the agent's `en.wav` drill recording (`Options.SmokeAudio`, DRILL-04) and, until that exists, `samples/jfk.wav` of the source being built. With no model or no sample, step 3 is skipped with a warning in the build output. BUILD.json records the steps that ran (`smoke.checks`).
- **Activation.** `current` moves atomically, then the speech service is restarted through the agent (`POST /services/whisper/restart`; a busy agent, `LAI-AGT-022`, is retried every 5 s for 60 s and then the switch is undone) or, with the agent down, `systemctl restart localai-whisper.service`. The check is `GET /` of the speech server answering 200 within 60 s of the restart. A node with no `whisper.env` yet (SVC-06 writes it) or with `whisper.enabled: false` has nothing to start: that is a warning, not a failure. Any failure puts the previous link back, restarts again and ends with `LAI-KIT-021`. After a switch to another commit `whisper.commit` is written into node.yaml; the switch is audited as `whisper.build.switch`.
- **Ready-made builds (KIT-05).** `aictl rebuild-whisper --prebuilt <file>` restores a build exported by `aictl kit export-build` (it goes through the same verification, smoke test, switch and rollback; a build for another Ubuntu release, processor, backend or graphics chip is `LAI-KIT-048`), a matching file is offered before compiling, and every build that is switched on is exported to the kit: [rebuild-kit.md](rebuild-kit.md) §4.2.
- **Codes.** A failed compile is `LAI-KIT-020` and a rejected build `LAI-KIT-021` (the codes `LAI-LLM-018` and `LAI-LLM-019` have for llama); the source and preflight codes (`LAI-KIT-001`, `002`, `010` to `014`) are shared.
- **Doctor.** `whisper.DoctorCheck` raises `LAI-SVC-012` when `/opt/localai/whisper.cpp/current/bin/whisper-server` is missing or not a program, and when `current` is a build for another backend than the configured one (a processor build on a node set to `cuda`). `internal/app/build.go` registers it next to the one of `kiwix.Installer.DoctorCheck`, enabled by `whisper.enabled` and with `whisper.backend` (`auto` meaning `llama.backend`) as the backend it checks. The agent writes the unit itself (`whisper.UnitWriter`, #322): at start when `whisper.enabled` is true and again when the `whisper` block of node.yaml changes, followed by a daemon-reload. The writer never starts, stops or restarts the unit; `aiagent setup units` (the installer, issue #153) writes it too.
- **CI.** The `whisper-build` workflow builds the CPU backend of the pinned release from a kit-style tarball inside `unshare -n` (no network from the preflight to the transcription of `samples/jfk.wav` with the `tiny.en` model) with `TestWhisperRealBuild`; the model and the source are fetched before the namespace is entered.

#### 4.2.2 Model selection
- `whisper.model: auto`: the first `engine: whisper` model in `profile.include.models` that has a verified BestCopy. Explicit id: that one, or `LAI-SVC-010` if not present.
- The model file is `files[kind=whisper]` (e.g. `ggml-small.bin` from HF `ggerganov/whisper.cpp` at a pinned revision). Catalog ids: `whisper-small` (small-8gb), `whisper-medium` or `whisper-large-v3-turbo` (others), per catalog.md §2.1. Multilingual models only (English and Spanish both needed).
- The agent writes `/etc/localai/whisper.env` (tmp + rename, mode 0640 root:localai) and restarts `localai-whisper` if the content changed.

#### 4.2.3 GPU or CPU (`whisper.device: auto`)
On a small GPU, whisper on the GPU competes with the LLM for VRAM. Rule, evaluated at each env regeneration and at survival entry:
- `gpu` if the backend is not `cpu` **and** `total_vram_mib − vram_needed_by(profile.survival.models[0]) − 1024 ≥ whisper model min_vram_mib` (values from the catalog `requirements.min_vram_mib`).
- otherwise `cpu` (`WHISPER_DEVICE_ARGS=--no-gpu`) and info code `LAI-SVC-013`.
On ai-n3 (8 GB, a ~6.4 GB survival model) this selects `cpu` for `whisper-small`. That is fine: about 2 s for a 5 s clip on the i7-10850H. When `device` resolves to `gpu`, the whisper model's `min_vram_mib` is the **whisper reservation `W_res`**: [llama-router.md](llama-router.md) §4.3.3 subtracts `W_res` in its dynamic fit while whisper is not yet running; once it runs, its VRAM use is already measured in `G_others`.

**What the code does (SVC-06).** `internal/svc/whisper/env.go` has the pure `Resolve` (model, threads, device, reservation, problems) and the `EnvWriter`; `fallback.go` has the start-failure counter; `internal/app/whisper.go` calls them.
- **Model.** `files[kind=whisper]` of the best-copy index (`ark.Index.BestCopy`), so a model counts only when its copy is verified. `auto` walks `profile.include.models` then `profile_overrides.add_models`; an explicit id that is unknown, not a whisper model or not installed is `LAI-SVC-010`, as is no model at all.
- **Device (`auto`).** `gpu` needs: the backend (`whisper.backend`, `auto` meaning `llama.backend`) is not `cpu`; the current build is not a `cpu` build; the rule of section 4.2.3 holds; and, when the sampler has measured it, the graphics memory free now is at least the model's `min_vram_mib`. Otherwise `cpu` with `LAI-SVC-013` (info). An explicit `device: cpu` or `backend: cpu` raises nothing. An explicit `device: gpu` is honoured, but the fallback below still overrides it.
- **Threads.** `auto` is `min(8, physical cores / 2)`, at least 1; physical cores are the distinct core ids of `/proc/cpuinfo` (`hardware.CPU.PhysicalCores`), not the logical CPUs.
- **Writing.** `whisper.env` is root:localai 0640 (tmp + rename), written only when its bytes differ, followed by exactly one restart of `localai-whisper`. With no model the unit is stopped, the file is left alone and `LAI-SVC-010` is raised. Triggers: agent start, a change of the `whisper` block, `drive.mounted`, `drive.unmounted` and `sync.item_done`. Survival entry does not trigger a regeneration yet (the inputs it reads do not change with the mode).
- **Fallback.** The agent watches the unit: each entry into `failed` or `auto-restart` while the device is `gpu` counts once; a unit that stays active 30 s clears the count. The second failure forces `cpu` in memory for this boot (a new agent process starts at zero), rewrites the env, restarts the unit and raises `LAI-SVC-013`.
- **Reservation.** `Selection.ReserveMiB` is `W_res` (the model's `min_vram_mib` on the gpu, 0 on the cpu). Passing it into the router's `NewEnv` is not wired yet (#25).

#### 4.2.4 The API the agent uses
whisper-server (examples/server in whisper.cpp) at `http://127.0.0.1:8081`:
- `POST /inference`, multipart, fields used: `file` (16 kHz mono PCM16 WAV), `response_format=verbose_json`, `language` (`auto` or a code), `temperature=0.0`, `temperature_inc=0.2`, `prompt` (optional), `no_timestamps=true`.
- Response (`verbose_json`): `{"task","language","duration","text","segments":[…]}`; the agent uses `text` (trimmed), `language` and `duration`. Language probability: from `detected_language_probability` if present, else omitted.
- `GET /` returns `200` (built-in page); used as the liveness check.
- `POST /load` is **not** used; a model change restarts the unit (simpler and resets VRAM).

The exact field names must be confirmed against `examples/server/server.cpp` at the pinned commit in the issue that pins it; the agent's client has a contract test against a recorded response from that commit.

#### 4.2.5 `/speech/stt` pipeline in the agent
1. Parse the multipart body (limit 25 MiB; stream to memory, no temp files).
2. Decode WAV in Go: support `WAVE_FORMAT_PCM` 16-bit and `WAVE_FORMAT_IEEE_FLOAT` 32-bit, and `WAVE_FORMAT_EXTENSIBLE` with those subformats. Anything else → `LAI-SVC-014`.
3. Downmix to mono (average), resample to 16 000 Hz with a windowed-sinc resampler (fixed 32 taps; fine for speech), convert to PCM16.
4. Reject if duration > `max_audio_seconds` or RMS < −60 dBFS (silence: "I couldn't hear anything. Try again closer to the microphone.").
5. Queue: one request in flight to whisper (whisper-server serialises anyway), up to 2 waiting; more → `429`.
6. POST to `/inference` with a 60 s timeout. Map the result to the response of §3.4.
7. Never log the transcript text (it may be private). Log only duration, language, elapsed time.

*Implementation (SVC-07, `internal/svc/whisper`):*
- **Route.** `whisper.STTService` (`NewSTT`, `Routes`), registered next to the piper routes; reads `whisper.enabled`, `whisper.model` and `whisper.max_audio_seconds` (default 120) from `node.yaml` live, the port from `ports.whisper`, and the model id for the answer from `WHISPER_MODEL_ID` in `whisper.env` (read only; `whisper.model` when the file has none; `whisper` as a last label).
- **Queue.** A request enters the queue (1 in flight + 2 waiting = 3 admitted) *before* its body is read, so at most three recordings are in memory; a fourth gets `429 LAI-SVC-015` with `Retry-After: 3`. The in-flight slot is taken after decoding, so whisper is never idle behind a slow upload. A caller that leaves while waiting frees its place.
- **Multipart.** Streamed with `mime/multipart` over `http.MaxBytesReader` (25 MiB); `audio` once, `language` and `prompt` (at most 4 KiB read, then 200 characters checked) and any other field ignored. Over the limit is `413 LAI-SVC-014` (`details.reason: too_large`). A malformed body, a second `audio`, a `language` outside `^[a-z]{2,3}$|^auto$` or a prompt over 200 characters is `400 LAI-AGT-020`; no `audio` or an empty one is `400 LAI-SVC-014`.
- **WAV.** A declared `data` size larger than the body is **cut to the body** (a recorder that was stopped, or a streaming header) and a partial last frame is dropped; any other chunk larger than the body is `truncated`; `data` before `fmt ` is refused. `details.reason` of `LAI-SVC-014`: `not_wav`, `truncated`, `no_format_chunk`, `bad_format_chunk`, `unsupported_encoding` (8-bit, 24-bit, 64-bit float, mu-law, an extensible sub-format other than PCM or float), `unsupported_channels`, `unsupported_rate` (0 or above 384 kHz), `no_data_chunk`, `bad_block_align`, `empty`, `too_long`, `silent`. Duration is checked before the samples are converted.
- **Errors from whisper-server.** Cannot connect, any status other than 200, a body that is not JSON, or `{"error": …}` in a 200: `503 LAI-SVC-011` (`details.reason: connect|status|bad_reply|error_field`), or `503 LAI-SVC-010` when no model id is known at all. `whisper.enabled: false` is `503 LAI-SVC-011` with `details.reason: disabled`. No answer within 60 s: `504 LAI-SVC-016`.
- **Language names.** whisper-server's `language` is the English name (`english`); the agent answers with the ISO code (`en`) through the whisper.cpp language table.
- **Messages.** Titles and fixes follow `X-LocalAI-UI-Language` (`en` or `es`); the silence sentence is `I couldn't hear anything. Try again closer to the microphone.` / `No pude oír nada. Intente otra vez más cerca del micrófono.`
- **Contract test.** `testdata/inference_verbose_json.sample.json` is written by hand in the `verbose_json` shape of whisper.cpp; it is replaced by a recording from the pinned build when the round-trip CI of #106 lands.

- Install: verify, extract to `/opt/localai/piper/2023.11.14-2/`, repoint `current`. Smoke test: `echo test | piper --model <voice> --output_raw | wc -c` > 10 000.
  *Implementation (SVC-08, `internal/svc/piper`):* `piper.Install(ctx, tarball, sha256, version)` follows the kiwix-tools installer: the kit tarball `<root>/kit/tools/piper/piper_linux_<x86_64|aarch64>.tar.gz` (`piper.KitPath`) is checked against the MANIFEST pin before a byte is extracted; every entry is validated (no absolute or `..` path, only sibling symlinks, no device or hard link); the archive's `piper/` top directory is stripped; the release must hold `piper` (made 0755), `espeak-ng-data/`, `libespeak-ng.so.1`, `libpiper_phonemize.so.1` and `libonnxruntime.so.*`; the new directory is smoke tested **before** it replaces anything, then `current` is repointed atomically. Both files (`piper_onnx` and `piper_config`) are required for `engine: piper` (catalog lint). Initial voices are single-speaker, so there is no speaker field.

#### 4.3.2 How the agent execs it
Per request:
```
argv: /opt/localai/piper/current/piper
      --model <best copy>/<voice>.onnx
      --config <best copy>/<voice>.onnx.json
      --espeak_data /opt/localai/piper/current/espeak-ng-data
      --output_raw
      --length_scale <piper.length_scale / speed>
      --sentence_silence 0.25
env:  LD_LIBRARY_PATH=/opt/localai/piper/current
      (nothing else; the environment is cleared)
stdin: the cleaned text, UTF-8, followed by "\n"
cred:  uid/gid of localai (SysProcAttr.Credential), cwd /var/lib/localai, new process group
rlimits: RLIMIT_AS 2 GiB, RLIMIT_CPU 60 s, RLIMIT_NOFILE 64
timeout: 10 s + 50 ms per character (max 110 s); on timeout, SIGKILL the process group
```
stdout is raw signed 16-bit little-endian mono PCM at `audio.sample_rate` from the voice's `.onnx.json` (usually 22 050 Hz). The agent prepends a 44-byte WAV header and streams the response (`Transfer-Encoding: chunked`) as audio arrives, so playback can start before synthesis ends. Up to 2 piper processes run at once; 4 more requests may wait. stderr is captured (first 4 KiB) for the `LAI-SVC-023` details.

*Implementation notes (SVC-08):*
- The process is started through `execx.Streamer` (`execx.Exec.Start`, with a fake for tests): an exact environment, the working directory, the credential, the stderr cap, and the three rlimits, which are applied to the child with `prlimit(2)` right after it starts (Go has no hook between fork and exec; the limits bound everything the program asks for from then on, and CPU time counts from its start). If a limit cannot be applied the process is killed, never run unlimited. The timeout and `Kill` take down the whole process group (a test proves a grandchild dies too).
- The text goes to stdin only, followed by one newline. Cleanup removes line breaks, so the text is one line and one utterance. Nothing but two catalog paths, a number and constants is in argv.
- The WAV header is written with the first audio, not before, with RIFF and data sizes `0xFFFFFFFF` ("until the end of the stream"; browsers, `aplay`, `sox` and `ffmpeg` read it). `piper.ParseHeader` is the strict reader (bounded, never allocates from a declared size) used by the tests. A voice whose `.onnx.json` has no `audio.sample_rate` between 8 000 and 48 000 is refused (`LAI-SVC-023`, `details.reason: bad_voice_config`). A last odd byte of PCM is dropped: a sample is two bytes.
- A failure **before** the first audio (non-zero exit, timeout, empty output, cannot start) is `500 LAI-SVC-023` with `details.reason` (`exit_status`, `timeout`, `empty_audio`, `start_failed`, `bad_voice_config`), `details.exit_code` and `details.stderr`. A failure **after** audio began aborts the connection, so the client sees a truncated stream, and logs `LAI-SVC-023`. When the client disconnects, the process group is killed and waited for and the slot is freed; a request that leaves the queue gives its place up. A binary that is missing or not executable is `503 LAI-SVC-020`.
- Limits: the text before cleanup is at most 64 KiB (more is `413 LAI-SVC-024`, so cleaning stays cheap); the audio of one request is bounded to 20 minutes. There are no temporary files: text goes in over a pipe and audio comes out over one, so there is nothing to clean up besides the process itself.
- Logs carry `chars`, `voice`, `language`, `elapsed_ms`, `audio_s` and the rule that chose the voice, never the text; a failure also carries the first line of stderr (cut at 200 bytes).

#### 4.3.3 Text cleanup
Before synthesis: strip Markdown markup (`*`, `_`, `#`, backticks, `>` quotes, table pipes), replace URLs with "link" / "enlace", collapse whitespace, drop emoji and control characters, and replace list bullets with a sentence break. Code blocks are replaced with "(code omitted)" / "(código omitido)". The cleanup is a pure function with table tests.

*Details (`piper.Clean`):* a Markdown link keeps its text and loses its target, an image keeps its alt text, `_` becomes a space (`snake_case` reads as two words), `#` is stripped only as a heading mark at the start of a line, and table cells are joined with ", " (the separator row is dropped). Headings, bullets, quotes and table rows each end with a sentence break (a "." is added when they have no punctuation of their own); a blank line ends the paragraph. A fenced block (three or more backticks or tildes; an unterminated one runs to the end) becomes one placeholder, and two placeholders in a row read once. Emoji, variation selectors, zero width joiners, keycaps, flags, control and invisible format characters are dropped; Spanish accents, `ñ`, `¿` and `¡` stay. The placeholder words follow the language of the **voice** that will speak (the cleanup first writes language-neutral marks, so a code block cannot tip the language detector). The 1 to 2000 character limit is counted in runes on the cleaned text; a text that is empty after cleanup is `400 LAI-AGT-020` (`details.reason: empty_after_cleanup`).

#### 4.3.4 Language selection
In order, the first that yields a verified voice wins:
1. `voice` in the request.
2. `language` in the request (`en`/`es`) → `piper.default_voice.<lang>`, or the first voice in the profile with that language.
3. `language: auto`: detect from the text. Detector: count matches against two built-in stop-word lists (about 60 words each: `the, and, is, of, you…` / `el, la, de, que, y, es, usted, por…`) plus Spanish-only characters (`ñ á é í ó ú ¿ ¡`, weight 3). Higher score wins; a tie or fewer than 3 hits falls through.
4. The Portal language sent by the caller in `X-LocalAI-UI-Language` (the Portal always sends it).
5. Any verified voice (sets `X-LocalAI-Fallback: true`, info `LAI-SVC-021`).
6. None → `503 LAI-SVC-022`.

*Details (`piper.Voices.Select`):* a voice is **verified** when `ark.Index.BestCopy` has a verified copy of its item whose manifest lists both a `piper_onnx` and a `piper_config` file, both inside the copy's directory. The candidates are the catalog's piper models, the profile's voices first in the profile's order, then the rest by id; the voice's language is the primary subtag of the first entry of its `languages`. A `voice` that is not a piper model of the catalog is `400 LAI-AGT-020` (`details.field: voice`, `details.reason: unknown_voice`); one that is in the catalog but not installed falls through to rule 2 like any rule that yields no voice. Rule 2 prefers `piper.default_voice.<lang>` when it is installed and of that language, then the first verified voice of the language. The detector's score for a language is its stop-word hits (whole words, accents folded; a word that means something in both languages is in neither list) plus 3 per Spanish-only character; the winner needs at least 3 and strictly more than the other (`piper.Detect`). `X-LocalAI-Fallback: true` is also sent when rule 4 answered a request for an explicit `en` or `es` that no installed voice speaks, since the header means "the requested language had no voice"; when the language was only detected or defaulted there is nothing to fall back from. `GET /speech/voices` lists the verified voices in candidate order and marks exactly one `default: true` per language: the voice rule 2 would pick (an empty list when `piper.enabled` is false or nothing is installed).

### 4.4 Maps

#### 4.4.1 Tile serving
- `GET /maps/tiles/<content-id>.pmtiles` opens `ark.BestCopy(content-id)`'s `.pmtiles` file and serves it with Go's `http.ServeContent`, which implements `Range`, `If-Range`, `HEAD` and `206`/`416`.
- `ETag: "<first 16 hex of the MANIFEST sha256>"`, `Cache-Control: no-cache` (the browser revalidates cheaply; a new version gets a new ETag), `Content-Type: application/vnd.pmtiles`. `Accept-Ranges: bytes`.
- Multi-range requests (`bytes=0-10,20-30`) return `416`; the pmtiles JS library only uses single ranges.
- Unknown id or no verified copy → `404` with `LAI-SVC-030`.
- File handles are opened per request and closed after, so an eject never finds a lingering handle for more than the duration of one response.
- *Details (`internal/maps`, SVC-09):* the `<content-id>` must be a `maps` item of the catalog built by `pmtiles_extract`; the file served is the first manifest file ending in `.pmtiles` that lies inside the copy's directory. The ETag is the first 16 hex digits of that file's `sha256` in the item's `MANIFEST.json` (a hash of the version and path if the manifest has none), so `If-Range` and `If-None-Match` compare a strong validator; no `Last-Modified` is sent. A header that does not parse (bad magic, version 2, bad zoom or bounds) is `404` with `LAI-SVC-034` (`details.reason: damaged`) and the map is left out of `catalog.json`. Parsed headers are cached by (path, sha256), so a new version is read again without any event. `localai_maps_tile_bytes_total` counts the body bytes of `GET` answers `200` and `206`. `/maps/assets/<path>` is `404` with `LAI-SVC-031` when no `map-assets` copy exists, and otherwise follows the static path rules of [agent.md](agent.md) §3.11 (no `..`, no dotfile, a symbolic link only inside the root). The default map in `catalog.json` is `maps.default_map` when that id is installed, else the first installed map in viewer order (the profile's maps first, then by survival tier, then by id). `display_name_es` is the English `display_name` until the catalog schema has a translated name.

- **Assets missing:** if `assets.available` is false, the viewer uses the same layers with every `symbol` layer removed (no text, no icons) and shows the banner "Map labels are missing. Names of places can't be shown." / "Faltan las etiquetas del mapa. No se pueden mostrar nombres." (`LAI-SVC-031`). Search still works (results are drawn as plain circles with an HTML label).
- **Several maps:** the map picker lists every map; the default is `maps.default_map`. Only one map is displayed at a time. When the view leaves a map's bounds, the viewer suggests the other map that contains the view, if any.
- UI elements (all large, keyboard reachable): search box, "Where am I", "Nearest: hospital / clinic / water / town" buttons, zoom +/−, a scale bar, a coordinate readout (decimal degrees and DMS) for the map center, and "Copy coordinates".
- *Details (SVC-10, `agent/ui/src/maps/`):*
  - *Build and paths.* The viewer is a second Vite build (`vite.maps.config.ts`, run by `npm run build` after the Portal build) into the same `dist/`: `maps.html` at the top and the hashed bundle in `dist/viewer/`. The agent serves the page at exactly `/maps/` (the Portal CSP of [survival-portal.md](survival-portal.md) §4.11, `Cache-Control: no-cache`) and the bundle at `/maps/viewer/<file>` (immutable). The bundle is **not** under `/maps/assets/`, which belongs to the ark `map-assets` item (fonts and sprites). `/maps` redirects to `/maps/`; any other unclaimed path under `/maps/` is `404`. MapLibre's worker runs from a `blob:` URL (`worker-src 'self' blob:`); `setWorkerUrl` and `setRTLTextPlugin` are never called. The few `http(s)` strings that libraries only display or link (the MapLibre logo link, two error-message hints) are rewritten at build time so the offline asset scan sees no URL in the bundle.
  - *Language.* `en`/`es` follows `?lang=`, else the Portal's `lai.portal.lang` choice (same origin), else the browser language; the viewer has its own toggle that writes the same key, and its own strings in `src/maps/i18n/{en,es}.json`.

A click, tap or right-click centers the map there; the red crosshair always marks the center and the readout (decimal and DMS, "Copy coordinates") describes it. **Where am I** reads `/maps/whereami` and flies to it (LAI-SVC-033 shows the GPS hint); **I am here** stores the *center* with `PUT /maps/whereami` (the keyboard way to set a position); typing coordinates in the search box (decimal or DMS) does the same; **Nearest** buttons call `/maps/nearest` from that position, or ask the person to use Where am I first. Search results and nearest places are drawn as dots with an HTML label (also when the labels are missing). `+` and `-` zoom when the focus is not in a text field.
  - *Offline test.* `agent/ui/e2e/maps-offline.spec.ts` aborts every request whose host is not `127.0.0.1` and fails if one is attempted; the fixture is a generated one-tile PMTiles file (so labels with real glyphs are checked by hand on a node, see the issue's manual test).

#### 4.4.4 Offline place search
Feasible offline with GeoNames, so it is in scope (not a limitation).
- **Data:** catalog item `places-central-america` (`kind: maps`, tier 1, source `url`, multiple files `https://download.geonames.org/export/dump/{CR,PA,NI,HN,SV,GT,BZ}.zip`, `version_policy: latest`, `checksum: computed`, `trust: tofu`, `refresh_days: 180`). GeoNames is CC BY 4.0; attribution is shown in the viewer. The fields are defined in [catalog.md](catalog.md) §3 (example item there). A larger `places-north-america` item can exist for the drive.
- **Plausibility check** at sync (in place of a pinned hash): every zip opens, each TSV row has 19 tab-separated columns, ≥ 99 % of rows parse, and the row count is at least 50 % of the previous version's. It is registered as the **content validator** for item `places-central-america` (and any `places-*` item) through the ark-sync `verifying` extension point ([ark-sync.md](ark-sync.md) §4.5); a failed validation is a verify failure → quarantine (`LAI-SYN-020`).
- **Index (in agent memory)**, built at agent start and on `sync.item_done` from the zip files directly (Go `archive/zip`, no extraction to disk), keeping:
  - feature class `P` (populated places) and `A` (`ADM1`, `ADM2`),
  - and these codes: `HSP`, `HSPC`, `HSPD` (hospitals and clinics), `SCH`, `CH`, `PP` (police), `AIRP`, `PRT`, `SPNG`, `WLL`, `RSV`, `LK`, `STM` (water), `MT`, `VLC`, `PK`, `PRK`, `BDG`, `RDJCT`.
  - Fields kept: geonameid, name, asciiname, up to 5 alternate names, lat, lon, feature class/code, country, admin1 name (from `admin1CodesASCII`-free mapping: the ADM1 rows of the same dump), population.
  - Budget: about 300 000 rows and < 60 MB RAM for Central America. The index is lazily built in a goroutine; until ready, search returns `503 {"state":"building"}`.
- **Normalisation:** lowercase, strip accents with a built-in fold table for Latin-1 and Latin Extended-A (`á→a`, `ñ→n`, `ü→u`, …), collapse spaces and punctuation. No `x/text` dependency.
- **Matching and ranking** (`/maps/search?q=`, `q` ≥ 2 chars): candidates = names (and alternates) where the normalised query is a prefix of the name (score 3), a prefix of a word in it (2), or a substring (1). Final score = match score × 10 + kind weight (P with population: `log10(pop+1)`; ADM: 4; hospitals/clinics: 3; others: 1) − `distance_km/100` when `near` is given. Return the top `limit` (≤ 50):
  ```json
  {"results": [{"name": "Hospital San Juan de Dios", "kind": "hospital", "lat": 9.9325, "lon": -84.0889, "admin1": "San José", "country": "CR", "distance_km": 1.2}], "attribution": "GeoNames (CC BY 4.0)"}
  ```
  `kind` is a friendly name from a fixed code→kind table (the UI translates `kind`), first match wins:
  | GeoNames feature | `kind` |
  |---|---|
  | code `HSP` | `hospital` |
  | code `HSPC`, `HSPD` | `clinic` |
  | code `SPNG`, `WLL`, `RSV`, `LK`, `STM` | `water` |
  | code `SCH` | `school` |
  | code `PP` | `police` |
  | code `AIRP` | `airport` |
  | code `MT`, `VLC` | `mountain` |
  | code `PK`, `PRK` | `park` |
  | class `P` with code `PPLC` or `PPLA`, or population ≥ 100 000 | `city` |
  | other class `P` | `town` |
  | anything else | `place` |
- **`/maps/nearest`**: linear scan with an equirectangular approximation over rows of that kind (fast enough at this size: < 20 ms), top 5.
- *Details (`internal/maps/places`, SVC-11):*
  - *Build.* `places.Manager` builds the index in a goroutine at agent start and after a verified `sync.item_done` of a `places-*` item or a drive mount or unmount, from the zip files of the best copy (the `.txt` inside each zip that is not the readme). A rebuild of an unchanged copy (same directory and version) is skipped; a new index replaces the old one with one atomic pointer store; a failed rebuild keeps the old index; no verified copy drops the index (state `absent`).
  - *Rows.* A row is kept when its class is `P`, or `A` with code `ADM1` or `ADM2`, or its code is in the list above. The admin1 name comes from the `ADM1` row with the same country and admin1 code, anywhere in the loaded dumps. The search keys of a row are its folded name, ascii name and up to 5 alternate names, de-duplicated. Memory: float32 coordinates, one string arena and interned admin1 names; 300 000 synthetic rows measured 43.7 MB of heap (`TestMemoryBudget`).
  - *Ranking.* Exactly the formula above (word prefix means the query follows a space in the folded name). Ties break by population (higher first), then by file order. `distance_km` is only in the answer when `near` (search) or the point (nearest) is given; it is equirectangular and rounded to 0.1 km; `lat` and `lon` are rounded to 5 decimals. `lang` is accepted (`en` or `es`) and does not change the answer: names are the GeoNames names.
  - *Routes.* `q` must have at least 2 characters after folding, `near` must be `lat,lon` in range, `limit` a positive integer (above 50 it is clamped to 50), `kind` one of the kinds above: anything else is `400` `LAI-AGT-020` with `details.field` and `details.reason`. While the first build runs both routes answer `503 {"state":"building"}` with `Retry-After: 5`; a first build that failed answers `503 {"state":"failed"}`; with no verified copy they answer `404` with `LAI-SVC-032`.
  - *Plausibility.* `places.Validate` (registered by `places.RegisterValidator` for every `places-*` item of kind `maps`): each zip opens and has a data file with rows, at least 99 % of all rows of a zip parse (19 columns, numeric id, coordinates in range, numeric population), and the total row count is at least half of the row count of the version in use (the serving index's total; no previous version means no check). A failure is a verify failure, and the item machine quarantines it with `LAI-SYN-020`.
  - *Maps readiness.* The "place index ready" bit: when the place manager is registered and has no verified copy, readiness carries `LAI-SVC-032` (warning, so `maps` is `degraded`, as in the `GET /services` example below). `catalog.json` `search` is `{available: true, places, source}` once an index is serving.
- Missing item → search box disabled with "Place search is not installed." / "La búsqueda de lugares no está instalada." (`LAI-SVC-032`); the map itself still works.

#### 4.4.5 Where am I
The browser Geolocation API is **never** used (offline it fails, and online it sends Wi-Fi data to a network service). Sources, in order:
1. **GPS via gpsd.** If `maps.gps` is `auto` or `gpsd` and something accepts TCP on `127.0.0.1:2947`, the agent connects, sends `?WATCH={"enable":true,"json":true};`, and keeps the last `TPV` report with `mode ≥ 2`.
2. **GPS via NMEA serial.** If `maps.gps` is `nmea:<device>`, or `auto` and a tty under `/sys/class/tty/tty{ACM,USB}*` belongs to a USB device with vendor id `1546` (u-blox) or a product string containing `GPS` or `GNSS`, the agent opens it read-only (`O_RDONLY|O_NOCTTY`, 9600 baud 8N1 via termios for `ttyUSB`; `ttyACM` ignores baud) and parses `$G?RMC` and `$G?GGA` sentences with checksum validation. Other serial devices are never opened by `auto`.
3. **Manual.** The user long-presses or right-clicks the map ("I am here" / "Estoy aquí"), picks a search result, or types coordinates (decimal `9.93, -84.08` or DMS `9°55'48"N 84°4'48"W`). Stored by `PUT /maps/whereami` in `state.json` (`maps.manual_location` = `{"lat","lon","label","set_at"}`, the `maps` sub-tree owned by this spec in [agent.md](agent.md) §3.5), so the desktop and any browser share it.
4. None: the map starts at the default map's center.

`GET /maps/whereami`:
```json
{"source": "gps", "lat": 9.93241, "lon": -84.07912, "accuracy_m": 8, "fix": "3d", "at": "2026-11-02T14:05:11Z", "label": null}
```
`source` ∈ `gps | manual | none`. A GPS fix older than 60 s is reported as `fix: "stale"`. A GPS source configured but silent for 2 minutes raises `LAI-SVC-033` (info, shown only on the map screen). The location never leaves the node (it is not in heartbeats or cloud reports).

Implementation details (`internal/maps`, `internal/maps/gps`):
- A stale GPS fix is still `source: gps, fix: stale` (the UI then offers the manual pin); a fresh GPS fix wins over a manual one; the manual location is used only when there has never been a GPS fix in this run. With `maps.gps: off` the GPS is ignored.
- `accuracy_m` is `eph` (or the larger of `epx`/`epy`) from gpsd, and `HDOP × 5` (rounded) from an NMEA `GGA` sentence; `null` when the receiver gives none. `fix` is `3d` from a gpsd mode 3 or a `GGA` with at least 4 satellites and an altitude, else `2d`. `at` is the agent's clock when the fix arrived.
- The response carries `"code": "LAI-SVC-033"` while a configured GPS is silent (omitted otherwise), so the map screen can show the hint; the same condition is the non-fast doctor check `svc.gps`. In `auto` a GPS counts as configured only once gpsd answered or a recognised receiver opened, so a laptop without a receiver never raises it.
- `PUT` also accepts `{"text": "9.93, -84.08"}` or `{"text": "9°55'48\"N 84°4'48\"W"}` (decimal or DMS, either order) instead of `lat`/`lon`; giving both is a 400.
- `maps.gps` that does not parse (`auto | off | gpsd | nmea:/dev/tty{ACM,USB,S,AMA}N`) is read as `off` so a typo never opens a serial port the owner did not choose. An explicit `nmea:<device>` is opened even if it is not on the allowlist (the owner chose it); `auto` only ever opens allowlisted receivers.
- The viewer UI (button, long-press, coordinate entry) belongs to the viewer issue (#108); this issue ships the agent side.

### 4.5 Vision

Vision is a normal LLM served by the router. This spec only fixes the requirements:
- The catalog model has `roles` containing `vision`, a `files[kind=mmproj]` entry, and `llama.mmproj_file_kind: mmproj` (catalog.md lint).
- [llama-router.md](llama-router.md) §4.2 writes, for that preset, `mmproj = <absolute path of the mmproj best copy>` and keeps `--mmproj-offload` on (default). If the mmproj has no verified copy, the preset is not generated and the model is `loadable: false` with `LAI-SVC-041`.
- `llama.ctx ≥ 8192` for vision models (images take hundreds to thousands of tokens).
- Clients send images as OpenAI chat content parts:
  ```json
  {"model": "<vision-model-id>", "stream": true, "temperature": 0.2, "max_tokens": 1024,
   "messages": [
     {"role": "system", "content": "<photo system prompt, survival-portal.md §4.7>"},
     {"role": "user", "content": [
       {"type": "text", "text": "What plant is this? Is it safe to eat?"},
       {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,/9j/4AAQ…"}}]}]}
  ```
  Images are resized client-side to at most 1024 px on the long side, JPEG quality 0.85 (≈ 150–400 KB), which bounds image tokens and upload size. The Portal posts this to `/chat/v1/chat/completions` (the key-injecting proxy, [survival-portal.md](survival-portal.md) §4.4).
- **Which model answers a photo:** if a loaded model has the `vision` role, use it. Else, if `models_max` allows another model and it fits ([llama-router.md](llama-router.md) §4.3), load the first vision model of `profile.survival.models` alongside (if that list has no vision model, the first vision model of `profile.include.models`, still subject to the fit rules). Else the Portal asks the user to switch brain (`capabilities.photo.reason: needs_switch`, which carries no doctor code; the Portal, not this spec, maps a "no brain running" state to `LAI-SVC-106`, [survival-portal.md](survival-portal.md) §3.5) (an explicit unload/load, about 20–60 s on ai-n3). No vision model loadable at all → `LAI-SVC-040`, and the Photo button explains it.
- The llama WebUI also accepts image attachments when the selected model has an mmproj, with no extra work from us.
- **Doctor check `svc.vision`** (`internal/svc/vision`): `LAI-SVC-041` (error, `details.model`) per vision model whose weights have a verified copy but whose mmproj does not; `LAI-SVC-040` (warning) when no catalog vision model is loadable; a vision model with `llama.ctx` below 8192 is reported as `LAI-CAT-013` relaxed to a warning (`details.rule: ctx_min`). The pure function `vision.Choose(loaded, profile, fit, models_max)` returns `{action, model_id, code}` and is what the Portal photo capability reads.

### 4.6 Health checks

The agent's health supervisor (`internal/svc/health`) runs these checks and keeps one state per service. This table is authoritative for the kiwix, whisper, piper and maps checks (intervals, timeouts, URLs); [agent.md](agent.md) §4.3.3 refers here.

| Service | Liveness (every 30 s, 3 s timeout) | Readiness detail | Deep check (on demand: `aictl doctor`, drill) |
|---|---|---|---|
| `llama` | owned by [llama-router.md](llama-router.md) | | |
| `kiwix` | systemd `ActiveState=active` and `GET http://127.0.0.1:8888/library/catalog/v2/entries?count=1` → `200` | `totalResults` equals the number of books in the merged library; mismatch → `degraded` (`LAI-SVC-004`, a ZIM was skipped as invalid) | full-text search in each tier-1 book: `GET /library/search?books.name=<name>&pattern=water&pageLength=1` returns ≥ 1 result |
| `whisper` | `ActiveState=active` and `GET http://127.0.0.1:8081/` → `200` | env model id equals the selected model | transcribe the bundled `drill/en.wav` and `drill/es.wav` (embedded in the agent); word error rate ≤ 30 % |
| `piper` | binary exists and is executable; at least one voice verified | one voice per Portal language (`en`, `es`) | synthesise "Test." / "Prueba." for each default voice: RMS > −40 dBFS, duration 0.3–5 s |
| `maps` | default map BestCopy present and header parses | assets present (the 3 font stacks' `0-255.pbf` and the sprite json); place index ready | fetch one tile at z=10 at the map center through `/maps/tiles/…` with Range and check it starts with the gzip magic `1f 8b` or is a valid MVT |

State values: `ok`, `degraded` (works with a problem), `down` (should run but doesn't respond), `missing_content` (nothing to serve; unit stopped on purpose), `disabled` (turned off in node.yaml), `starting` (first 60 s after a start; failures don't count yet).

**Supervisor rules:**
- 3 consecutive liveness failures of an `active` unit → restart it (`LAI-SVC-050`, info). At most 3 restarts per hour per service; then stop trying, state `down`, raise `LAI-SVC-051` (red in survival mode, yellow otherwise).
- A unit in systemd `failed` state is restarted under the same budget.
- In survival mode, `require_services` from the profile (modes.md §3) that are `down` or `missing_content` are shown in the Portal status strip.

**How the supervisor applies them** (SVC-01, `internal/svc/health`):
- *State.* Per service, in this order: not enabled in `node.yaml` → `disabled` (never probed, never restarted); `Content` says nothing to serve → `missing_content` (never probed, never restarted, with the code the probe names: `LAI-SVC-001`, `010`, `022`, `030`); a unit that is `activating` → `starting`; a unit that is not active (stopped by the operator, or `failed`) → `down` with `LAI-SVC-002` / `011`; active but not probed yet → `starting`; probe passes → `ok`, or `degraded` when the readiness reports a problem of warning or worse; probe fails within 60 s of the unit's start → `starting` and the failure does not count; fails after that → `degraded` for failures 1 and 2, and at the 3rd the unit is restarted (state `starting` again). `down` also is the state of an active unit that fails while the restart budget is spent. A service without a unit (piper, maps) has no restart: its liveness failure is `down` at once, with the code the probe names (`LAI-SVC-020`, `034`).
- *Probes.* Liveness every 30 s, and on every 10 s tick while the service is `starting` and has not answered, so it is `ok` within one tick of answering; each probe call is bounded to 3 s. A unit that just became active (seen through `Manager.Subscribe`) is probed at once. A unit stopped on purpose is never restarted: only `failed` and an active-but-unresponsive unit are.
- *Budget.* A sliding 1-hour window per service, in memory; a restart that fails to run counts too. When it is spent the supervisor does not restart, raises `LAI-SVC-051` (first in `problems`, then the `down` code) and waits: the window frees by itself an hour after the oldest restart, and the supervisor then tries again. `LAI-SVC-050` (info) stays in `problems` while the service has a restart inside the window, and never makes it `degraded`.
- *Events.* `service.state` is published once per change of the health state (a change of the systemd `active`/`sub` alone is not a transition); the first observation after agent start is the baseline and publishes nothing. `code` is the first problem of the new state, only when the new state is not `ok`; `unit` is `null` for piper and maps.
- *Piper's checks (SVC-08, `piper.Service.Spec`).* No unit, `DownCode` LAI-SVC-020, enabled follows `piper.enabled`. Liveness: the binary is an executable file (`LAI-SVC-020`) and at least one voice is verified (`LAI-SVC-022`). Content: no verified voice is `missing_content` with `LAI-SVC-022`. Readiness: the verified voice ids, "N voices", and `LAI-SVC-021` (warning, so `degraded`) for each of `en` and `es` that has no verified voice. Deep: "Test." with the English default voice and "Prueba." with the Spanish one, each through the same exec contract and the same concurrency limiter as a request (a busy node skips the check, since busy is no finding); a failed run, a duration outside 0.3 to 5 s or an RMS of -40 dBFS or less is `LAI-SVC-023`; a missing binary is `LAI-SVC-020`.
- *Maps' checks (SVC-09, `(*maps.Maps).Spec`).* No unit, `DownCode` LAI-SVC-034, enabled follows `maps.enabled` (default on). Liveness: the default map has a verified copy and its header parses (`LAI-SVC-030` when no map is installed, `LAI-SVC-034` when the installed ones are damaged). Content: no map with a verified copy is `missing_content` with `LAI-SVC-030`. Readiness: the installed map ids, "N maps", `LAI-SVC-031` when the first glyph range (`0-255.pbf`) of any of the three font stacks or `sprites/v4/light.json` is missing, and `LAI-SVC-034` when an installed map is damaged; the "place index ready" bit is added by SVC-11. Deep: the tile at the center of the default map at z=10 (or the nearest zoom the file has) is found by walking the PMTiles directories with HTTP Range reads through the tile handler itself and must start with the gzip magic (or be an uncompressed vector tile); a missing or malformed tile is `LAI-SVC-034`.
- *Where the Go seams are.* A service plugs in with `health.Spec{Name, Unit, Enabled, Probe, DownCode, Interval}` and a `health.Probe` of four methods (`Liveness`, `Content`, `Readiness`, `Deep`; `health.FuncProbe` fills the ones a service does not need). `health.KiwixSpec` and `health.WhisperSpec` carry the unit and the HTTP liveness of this table; the readiness, content and deep checks of kiwix, whisper, piper and maps are plugged in by SVC-03, SVC-06, SVC-08, SVC-09 and SVC-11. `Supervisor` (an `app.Worker` named `svc-health`) serves `Records` (the rows of `GET /services`, via `api.ServicesDeps.Health`), `Snapshot` (`services.Status` rows for `/status`; `health.Combine(watcher, supervisor)` merges them with llama's), `Reduced` (the cloud heartbeat form), `Flagged` (the survival `require_services` that are `down` or `missing_content`, for the Portal), `Deep`, and the doctor checks `svc.health` (fast, cached) and `svc.deep` (slow, on demand). When the supervisor is wired, `services.Watcher` is limited to llama (`WatcherOptions.Only`) so only one component publishes `service.state` per service.

## 6. Security considerations

- All three listeners (8888, 8081, and the agent paths) are loopback-only. kiwix-serve and whisper-server have no auth by design (overview.md §3.4). Any local user can reach them; they expose only public content (the library) or a transcription service.
- Units run as `localai` with systemd hardening (§3.3). kiwix-serve gets `PrivateDevices`, `MemoryDenyWriteExecute` and a read-only filesystem view; whisper needs GPU devices so it gets less.
- Piper runs as `localai` with a cleared environment, rlimits, a timeout and a fixed argv. Text goes over stdin, never argv, so there is no injection surface.
- WAV parsing is done in Go with strict bounds; malformed headers can't cause over-reads (fuzz test).
- `--blockexternal` stops Kiwix pages from linking out to the internet; the agent's `/library/` proxy also sets `Content-Security-Policy: default-src 'self' 'unsafe-inline' data:; connect-src 'self'` on proxied HTML, so a ZIM page can't fetch remote resources even online.
- Transcripts, synthesised text and locations are not logged and are never sent to the cloud.
- The GPS reader only opens devices it can identify as GPS, so `auto` never interferes with other serial hardware.
- `PUT /maps/whereami` requires a same-origin `Origin` header (CSRF defence, security-model.md §2).

## 7. Observability

Logs (slog, `component` ∈ `kiwix`, `whisper`, `piper`, `maps`, `health`). Keys: `service`, `state`, `from`, `to`, `code`, `elapsed_ms`, `audio_s`, `chars`, `voice`, `language`, `model`, `map`, `books`.
```json
{"level":"INFO","msg":"stt done","component":"whisper","audio_s":3.2,"language":"en","elapsed_ms":1840,"model":"whisper-small"}
{"level":"WARN","msg":"service restarted","component":"health","service":"kiwix","code":"LAI-SVC-050","failures":3}
```
Events: `service.state`. Metrics (in `GET /api/v1/status?counters=1` → `node.counters`, where agent.md §7 puts every counter; `/status` `services` is an array, so it has no `metrics` key): `localai_stt_requests_total{result}`, `localai_stt_seconds` (histogram buckets 1, 2, 5, 10, 30, 60), `localai_tts_requests_total{voice,result}`, `localai_tts_seconds` (buckets 0.5, 1, 2, 5, 10, 30), `localai_maps_tile_bytes_total`, `localai_service_restarts_total{service}`. They live in `health.Metrics`; its `Counters()` is the map a `CounterView` merges into `node.counters`: a counter is a number under its name with the labels in braces, a histogram is `{count, sum, buckets}` with cumulative buckets and `+Inf`.

### 9.3 Manual on ai-n3
1. `aictl services` → kiwix, whisper, piper, maps all `ok` (whisper `device: cpu`).
2. `curl -s 'http://127.0.0.1:7070/library/search?books.name=wikipedia_en_medicine_maxi&pattern=bleeding&pageLength=1' | head` → HTML with a result.
3. Record a WAV: `arecord -f S16_LE -r 16000 -c 1 -d 4 /tmp/t.wav` and say "how do I purify water"; then `curl -s -H "Authorization: Bearer $(sudo cat /etc/localai/agent-token)" -F audio=@/tmp/t.wav http://127.0.0.1:7070/api/v1/speech/stt | jq .` → the text, `"language": "en"`.
4. `curl -s -H "Authorization: Bearer …" -H 'Content-Type: application/json' -d '{"text":"Hierva el agua durante un minuto."}' http://127.0.0.1:7070/api/v1/speech/tts -o /tmp/s.wav -D - | grep X-LocalAI` → `X-LocalAI-Language: es`; `aplay /tmp/s.wav` is Spanish speech.
5. Turn Wi-Fi off. Open `http://127.0.0.1:7070/maps/` → the map with labels; search "Liberia" → the Costa Rican city first; "Nearest: hospital" lists hospitals.
6. With a USB GPS (if available) → "Where am I" centres on the fix; without → manual pin persists after reload.
7. Load the vision model and post a photo through the Portal → a description in the UI language.
