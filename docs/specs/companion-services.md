# Spec: Companion services (library, speech-to-text, text-to-speech, maps, vision)

> **Status:** approved design · **Epic:** E4 · **Code:** `agent/internal/svc/kiwix/`, `agent/internal/svc/whisper/`, `agent/internal/svc/piper/`, `agent/internal/maps/`, `agent/internal/svc/health/`, `agent/ui/src/maps/` · **Doctor area:** `LAI-SVC` (codes 001–099; 100–149 belong to [survival-portal.md](survival-portal.md))
> Canonical names: [overview.md](../architecture/overview.md) §3. Content comes from [ark-sync.md](ark-sync.md) (BestCopy). Router presets: [llama-router.md](llama-router.md). API routes: [agent.md](agent.md) §3.8.

---

## 1. Purpose and scope

Everything besides the LLM that a node needs to be useful offline: an offline library (Kiwix), speech-to-text (whisper.cpp), text-to-speech (Piper), offline maps, and image understanding (a vision LLM served by the router). This spec defines how each is installed, configured from the catalog, started, health-checked and exposed through the agent.

In scope:
- `localai-kiwix.service`: kiwix-serve, the merged library, the `/library/` proxy.
- `localai-whisper.service`: whisper.cpp build per backend, model selection, `POST /api/v1/speech/stt`.
- Piper: binary and voices, per-request exec, `POST /api/v1/speech/tts`, language selection.
- Maps: the MapLibre viewer, pmtiles range serving, local style/glyphs/sprites, offline place search, "where am I".
- Vision: the requirements on the router preset and the photo request format.
- Health checks and how they are surfaced.

Non-goals:
- Building a chat UI. The llama WebUI (`/chat/`) and the Portal's small screens ([survival-portal.md](survival-portal.md)) are the UIs.
- Routing or turn-by-turn navigation on the map. The viewer shows where things are; it doesn't plan routes.
- Online map tiles, online geocoding, or the browser Geolocation API (which in Chromium asks a network service). None are used, ever.
- Voice cloning, wake words, always-listening microphones.
- Translating Kiwix content.

## 2. Concepts

| Term | Meaning |
|---|---|
| **Merged library** | `/var/lib/localai/kiwix/library.xml`: one Kiwix library listing the best copy of every verified ZIM across all mounted content roots |
| **Per-root library** | `<root>/kiwix/library.xml`: lists only that root's ZIMs with relative paths, so a drive can be served by kiwix-serve on any machine |
| **Voice** | A Piper model: `<voice>.onnx` + `<voice>.onnx.json`, one catalog model with `engine: piper` |
| **Map** | One verified `pmtiles` file (`maps/<content-id>/*.pmtiles`) |
| **Map assets** | `maps/assets/` from the `map-assets` item: `fonts/<fontstack>/<range>.pbf` and `sprites/v4/<flavor>{.json,.png,@2x.json,@2x.png}` |
| **Place index** | An in-memory search index built from the GeoNames per-country dumps (item `places-central-america`) |

`$WHISPER_DEVICE_ARGS` is unbraced on purpose: systemd splits it into words, and an empty value adds no argument. `PrivateDevices` is **not** set, because the GPU device nodes are needed.

Piper has no unit. It is exec'd per request by the agent (§4.3).

Both units are `enabled` by the installer. The agent starts, stops and restarts them through systemd D-Bus (`org.freedesktop.systemd1`), never by spawning `systemctl` with a shell.

### 3.4 HTTP: speech (routes fixed in agent.md)

**`POST /api/v1/speech/stt`** (auth: bearer, session, or a Portal-scope session in survival mode, see [survival-portal.md](survival-portal.md) §3.3). `multipart/form-data`:
| Field | Required | Notes |
|---|---|---|
| `audio` | yes | `audio/wav` (RIFF, PCM 16-bit or 32-bit float, any rate, 1–2 channels). ≤ 25 MiB and ≤ `whisper.max_audio_seconds` |
| `language` | no | `auto` (default), `en`, `es`, or any whisper language code |
| `prompt` | no | ≤ 200 chars, passed as whisper's initial prompt (e.g. names) |

Response `200`:
```json
{"text": "How do I clean a deep cut?", "language": "en", "language_probability": 0.97, "duration_s": 3.2, "model": "whisper-small", "elapsed_ms": 1840}
```
Errors (all JSON `{code, title, fix}`, see agent.md error shape):
| Status | Code | When |
|---|---|---|
| 400 | `LAI-SVC-014` | not WAV, unsupported encoding, too long, empty, or silent (RMS below −60 dBFS) |
| 413 | `LAI-SVC-014` | larger than 25 MiB |
| 429 | `LAI-SVC-015` | 2 requests already queued |
| 503 | `LAI-SVC-010` / `011` | no model / server down |
| 504 | `LAI-SVC-016` | whisper took longer than 60 s |

**`POST /api/v1/speech/tts`** (same auth). JSON:
```json
{"text": "Press firmly on the wound with a clean cloth.", "voice": null, "language": "en", "speed": 1.0}
```
- `text`: 1–2000 chars after cleanup (§4.3.3). Longer → `413 LAI-SVC-024` (callers split by sentence).
- `voice`: a catalog piper model id, optional.
- `language`: `en`, `es`, or `auto` (default).
- `speed`: 0.7–1.5, multiplies `piper.length_scale` inversely.

Response `200`, `Content-Type: audio/wav`, headers `X-LocalAI-Voice: piper-en-medium`, `X-LocalAI-Language: en`, `X-LocalAI-Fallback: true` when the requested language had no voice. Errors: `503 LAI-SVC-022` (no voice), `500 LAI-SVC-023` (piper failed), `429 LAI-SVC-015` (more than 2 concurrent syntheses + 4 queued).

**`GET /api/v1/speech/voices`** (new route, see §11): `{"voices":[{"id":"piper-en-medium","language":"en","display_name":"English (US), medium","default":true}]}`. Needed by the Portal to show the voice picker.

### 3.5 HTTP: library and maps (non-API agent paths)

These live outside `/api/v1`. They are in the unauthenticated survival set (security-model.md §3) and are loopback-only like everything else. They accept only `GET` and `HEAD`, except `PUT/DELETE /maps/whereami` (same-origin check required).

| Path | Behaviour |
|---|---|
| `/library/…` | Reverse proxy to `http://127.0.0.1:8888/library/…` (path preserved, because kiwix-serve runs with `--urlRootLocation=/library`). Hop-by-hop headers removed; `X-Forwarded-*` not added. `503` with a bilingual HTML page "The library is not running" + `LAI-SVC-002` if the upstream is down (a per-mount exception to the generic `502` of [agent.md](agent.md) §3.11). Response timeout 600 s |
| `/maps/` | The viewer (embedded SPA) |
| `/maps/catalog.json` | Available maps and assets (§4.4.2) |
| `/maps/tiles/<content-id>.pmtiles` | The best copy of that map, with HTTP Range (§4.4.1) |
| `/maps/assets/<path>` | Files under the best copy of `maps/assets/` |
| `/maps/search?q=&near=<lat>,<lon>&limit=20&lang=en` | Place search (§4.4.4) |
| `/maps/nearest?lat=&lon=&kind=<kind>&limit=5` | Nearest places of a kind (§4.4.4) |
| `/maps/whereami` | `GET` current position; `PUT {lat, lon, label?}` set manually; `DELETE` clear (§4.4.5) |

## 4. Behaviour

### 4.1 kiwix-serve

#### 4.1.1 Binary
- Source: the official static release tarball `kiwix-tools_linux-x86_64-<ver>.tar.gz` (or `linux-aarch64`) from `https://download.kiwix.org/release/kiwix-tools/`. It is a catalog `kit` item (`kit-kiwix-tools`, source `url`, pinned sha256), so the same tarball is in `kit/tools/kiwix-tools/` ([rebuild-kit.md](rebuild-kit.md) §Contents).
- Install (installer, and `aictl kit install kiwix-tools`): verify the tarball sha256 against the kit MANIFEST, extract to `/opt/localai/kiwix-tools/<ver>/` (files `kiwix-serve`, `kiwix-manage`, `kiwix-search`), `chmod 0755`, then atomically repoint `current` (`ln -sfn <ver> current.tmp && mv -T current.tmp current`). Keep the previous version directory.
- Check: `kiwix-serve --version` must print the expected version. The flags used in §3.3 must be checked against `kiwix-serve --help` of the pinned version in the issue that pins it.

#### 4.1.2 Library regeneration
Triggered on agent start, on `sync.item_done` for a kiwix item, on `drive.mounted` / `drive.unmounted`, and on `aictl services restart kiwix`. Debounced: at most once per 10 s.
1. For each catalog kiwix item, get `ark.BestCopy(id)`. Skip items without a verified copy. On an `unclean` drive, wait for the serve-time verification ([ark-sync.md](ark-sync.md) §4.1.3).
2. If two items have the same ZIM `Name` metadata (possible across catalog revisions), keep the one with the newest date.
3. Build into a temp file in the same directory: `kiwix-manage /var/lib/localai/kiwix/library.xml.tmp add <zim1> <zim2> …` (absolute paths), run as `localai`, timeout 120 s. Exit ≠ 0 → `LAI-SVC-005`, keep the old library.
4. Validate: the temp file parses as XML and has one `<book>` per ZIM added.
5. `rename` the temp file over `library.xml`. kiwix-serve, started with `--monitorLibrary`, reloads it within a few seconds.
6. If the library is now empty: stop `localai-kiwix`, set the service state `missing_content`, raise `LAI-SVC-001`. If it was empty before and isn't now: start the unit.
7. Ejecting or a surprise removal: after the rename, wait 10 s, then check `/proc/<kiwix pid>/fd` for files under the removed mount. If any remain, restart `localai-kiwix` (kiwix-serve may hold old ZIMs open after a reload).

Per-root libraries are regenerated the same way, but with `cwd=<root>/kiwix` and relative paths (`<id>/<file>.zim`), and only for that root's ZIMs, after every kiwix swap on a writable root.

#### 4.1.3 Article URLs
kiwix-serve exposes each book under its name with the date (`wikipedia_en_all_nopic_2026-10`) and, because date aliases are on by default, also without the date (`wikipedia_en_all_nopic`). Everything that links into the library (Portal first-aid links, the drill) uses the **undated alias**: `/library/content/<book-name-without-date>/<article-path>`. These links keep working across ZIM updates.

The agent exposes the mapping content id → book name in `GET /api/v1/services` (`kiwix.books[]`), so the Portal never hard-codes dates.

### 4.2 whisper.cpp server

#### 4.2.1 Build per backend
whisper.cpp is built from the pinned commit (`whisper.commit`) using the kit tarball `kit/src/whisper.cpp-<commit>.tar.gz` (online or offline; the tarball is always used, so online and offline builds are identical). Builder: the same code path as `aictl rebuild-llama` ([rebuild-kit.md](rebuild-kit.md) §rebuild-llama), exposed as `aictl rebuild-whisper` ([aictl.md](aictl.md) §4.23a). Ownership: SVC-05 owns this build target, the smoke test, the unit and the base `aictl rebuild-whisper` command; KIT-05 ([rebuild-kit.md](rebuild-kit.md) §10) adds `--prebuilt`, `--from-kit`, `--dry-run` and export.

```
src=/var/lib/localai/build/whisper.cpp-<commit>
tar -xzf kit/src/whisper.cpp-<commit>.tar.gz -C /var/lib/localai/build/
cmake -S $src -B $src/build-<backend> -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_SHARED_LIBS=OFF \
  -DWHISPER_BUILD_EXAMPLES=ON -DWHISPER_BUILD_TESTS=OFF -DWHISPER_SDL2=OFF \
  -DGGML_NATIVE=ON \
  <backend flags>
cmake --build $src/build-<backend> --target whisper-server whisper-cli -j <jobs>
```
| Backend | Flags |
|---|---|
| `cuda` | `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=<cc>` where `<cc>` is the GPU compute capability without the dot (`75` for the RTX 2070, `89` for the RTX 4080), from `nvidia-smi --query-gpu=compute_cap --format=csv,noheader` |
| `vulkan` | `-DGGML_VULKAN=ON` |
| `cpu` | none (OpenBLAS is not used, to keep dependencies minimal) |

`BUILD_SHARED_LIBS=OFF` gives a self-contained `whisper-server` (only system libraries such as libcudart, libvulkan and libc are dynamic), so it can be copied into `/opt` without rpath problems. Install: `/opt/localai/whisper.cpp/builds/<commit[:9]>-<backend>/bin/{whisper-server,whisper-cli}`, then repoint `current` atomically. Smoke test before repointing: `whisper-cli -m <model> -f <bundled en.wav> -l en -nt` exits 0 and prints non-empty text. If no whisper model has a verified copy yet (fresh node), the transcription step is skipped with a warning in the build output and `whisper-cli --help` exiting 0 is the smoke test (as rebuild-kit.md §4.3.3 does for llama). Keep the last 2 builds.

`backend: auto` uses the llama backend from `node.yaml`. A node can force `cpu` (e.g. to keep all VRAM for the LLM, §4.2.3).

#### 4.2.2 Model selection
- `whisper.model: auto`: the first `engine: whisper` model in `profile.include.models` that has a verified BestCopy. Explicit id: that one, or `LAI-SVC-010` if not present.
- The model file is `files[kind=whisper]` (e.g. `ggml-small.bin` from HF `ggerganov/whisper.cpp` at a pinned revision). Catalog ids: `whisper-small` (small-8gb), `whisper-medium` or `whisper-large-v3-turbo` (others), per catalog.md §2.1. Multilingual models only (English and Spanish both needed).
- The agent writes `/etc/localai/whisper.env` (tmp + rename, mode 0640 root:localai) and restarts `localai-whisper` if the content changed.

#### 4.2.3 GPU or CPU (`whisper.device: auto`)
On a small GPU, whisper on the GPU competes with the LLM for VRAM. Rule, evaluated at each env regeneration and at survival entry:
- `gpu` if the backend is not `cpu` **and** `total_vram_mib − vram_needed_by(profile.survival.models[0]) − 1024 ≥ whisper model min_vram_mib` (values from the catalog `requirements.min_vram_mib`).
- otherwise `cpu` (`WHISPER_DEVICE_ARGS=--no-gpu`) and info code `LAI-SVC-013`.
On ai-n3 (8 GB, a ~6.4 GB survival model) this selects `cpu` for `whisper-small`. That is fine: about 2 s for a 5 s clip on the i7-10850H. When `device` resolves to `gpu`, the whisper model's `min_vram_mib` is the **whisper reservation `W_res`**: [llama-router.md](llama-router.md) §4.3.3 subtracts `W_res` in its dynamic fit while whisper is not yet running; once it runs, its VRAM use is already measured in `G_others`.

#### 4.2.4 The API the agent uses
whisper-server (examples/server in whisper.cpp) at `http://127.0.0.1:8081`:
- `POST /inference`, multipart, fields used: `file` (16 kHz mono PCM16 WAV), `response_format=verbose_json`, `language` (`auto` or a code), `temperature=0.0`, `temperature_inc=0.2`, `prompt` (optional), `no_timestamps=true`.
- Response (`verbose_json`): `{"task","language","duration","text","segments":[…]}`; the agent uses `text` (trimmed), `language` and `duration`. Language probability: from `detected_language_probability` if present, else omitted.
- `GET /` returns `200` (built-in page); used as the liveness check.
- `POST /load` is **not** used; a model change restarts the unit (simpler and resets VRAM).

The exact field names must be confirmed against `examples/server/server.cpp` at the pinned commit in the issue that pins it; the agent's client has a contract test against a recorded response from that commit.

#### 4.2.5 `/speech/stt` pipeline in the agent
1. Parse the multipart body (limit 25 MiB; stream to memory, no temp files).
2. Decode WAV in Go: support `WAVE_FORMAT_PCM` 16-bit and `WAVE_FORMAT_IEEE_FLOAT` 32-bit, and `WAVE_FORMAT_EXTENSIBLE` with those subformats. Anything else → `LAI-SVC-014`.
3. Downmix to mono (average), resample to 16 000 Hz with a windowed-sinc resampler (fixed 32 taps; fine for speech), convert to PCM16.
4. Reject if duration > `max_audio_seconds` or RMS < −60 dBFS (silence: "I couldn't hear anything. Try again closer to the microphone.").
5. Queue: one request in flight to whisper (whisper-server serialises anyway), up to 2 waiting; more → `429`.
6. POST to `/inference` with a 60 s timeout. Map the result to the response of §3.4.
7. Never log the transcript text (it may be private). Log only duration, language, elapsed time.

### 4.3 Piper

#### 4.3.1 Binary and voices
- Binary: the `rhasspy/piper` C++ release `2023.11.14-2`, assets `piper_linux_x86_64.tar.gz` / `piper_linux_aarch64.tar.gz` (pinned sha256 in the catalog, kit item `kit-piper`). It bundles `piper`, `libespeak-ng.so.1`, `libonnxruntime.so.*`, `libpiper_phonemize.so.1` and `espeak-ng-data/`. That repo is archived; we use it because it is a self-contained binary with no Python runtime. (Its successor, piper1-gpl, is a Python package; rejected for the same reasons as ADR-0001.)
- Install: verify, extract to `/opt/localai/piper/2023.11.14-2/`, repoint `current`. Smoke test: `echo test | piper --model <voice> --output_raw | wc -c` > 10 000.
- Voices: catalog models with `engine: piper` from HF `rhasspy/piper-voices` at a pinned revision, `files` kinds `piper_onnx` + `piper_config`, stored in `<root>/speech/piper/<voice-id>/`. Voice ids are lowercase slugs `piper-<lang>-<quality>` ([catalog.md](catalog.md) §2.1); the upstream voice name lives only in the file names. Initial set: `piper-en-medium` = `en/en_US/lessac/medium/en_US-lessac-medium`, `piper-es-medium` = `es/es_MX/ald/medium/es_MX-ald-medium` (Latin American Spanish). Both files (`piper_onnx` and `piper_config`) are required for `engine: piper` (catalog lint). Initial voices are single-speaker, so there is no speaker field.

#### 4.3.2 How the agent execs it
Per request:
```
argv: /opt/localai/piper/current/piper
      --model <best copy>/<voice>.onnx
      --config <best copy>/<voice>.onnx.json
      --espeak_data /opt/localai/piper/current/espeak-ng-data
      --output_raw
      --length_scale <piper.length_scale / speed>
      --sentence_silence 0.25
env:  LD_LIBRARY_PATH=/opt/localai/piper/current
      (nothing else; the environment is cleared)
stdin: the cleaned text, UTF-8, followed by "\n"
cred:  uid/gid of localai (SysProcAttr.Credential), cwd /var/lib/localai, new process group
rlimits: RLIMIT_AS 2 GiB, RLIMIT_CPU 60 s, RLIMIT_NOFILE 64
timeout: 10 s + 50 ms per character (max 110 s); on timeout, SIGKILL the process group
```
stdout is raw signed 16-bit little-endian mono PCM at `audio.sample_rate` from the voice's `.onnx.json` (usually 22 050 Hz). The agent prepends a 44-byte WAV header and streams the response (`Transfer-Encoding: chunked`) as audio arrives, so playback can start before synthesis ends. Up to 2 piper processes run at once; 4 more requests may wait. stderr is captured (first 4 KiB) for the `LAI-SVC-023` details.

#### 4.3.3 Text cleanup
Before synthesis: strip Markdown markup (`*`, `_`, `#`, backticks, `>` quotes, table pipes), replace URLs with "link" / "enlace", collapse whitespace, drop emoji and control characters, and replace list bullets with a sentence break. Code blocks are replaced with "(code omitted)" / "(código omitido)". The cleanup is a pure function with table tests.

#### 4.3.4 Language selection
In order, the first that yields a verified voice wins:
1. `voice` in the request.
2. `language` in the request (`en`/`es`) → `piper.default_voice.<lang>`, or the first voice in the profile with that language.
3. `language: auto`: detect from the text. Detector: count matches against two built-in stop-word lists (about 60 words each: `the, and, is, of, you…` / `el, la, de, que, y, es, usted, por…`) plus Spanish-only characters (`ñ á é í ó ú ¿ ¡`, weight 3). Higher score wins; a tie or fewer than 3 hits falls through.
4. The Portal language sent by the caller in `X-LocalAI-UI-Language` (the Portal always sends it).
5. Any verified voice (sets `X-LocalAI-Fallback: true`, info `LAI-SVC-021`).
6. None → `503 LAI-SVC-022`.

### 4.4 Maps

#### 4.4.1 Tile serving
- `GET /maps/tiles/<content-id>.pmtiles` opens `ark.BestCopy(content-id)`'s `.pmtiles` file and serves it with Go's `http.ServeContent`, which implements `Range`, `If-Range`, `HEAD` and `206`/`416`.
- `ETag: "<first 16 hex of the MANIFEST sha256>"`, `Cache-Control: no-cache` (the browser revalidates cheaply; a new version gets a new ETag), `Content-Type: application/vnd.pmtiles`. `Accept-Ranges: bytes`.
- Multi-range requests (`bytes=0-10,20-30`) return `416`; the pmtiles JS library only uses single ranges.
- Unknown id or no verified copy → `404` with `LAI-SVC-030`.
- File handles are opened per request and closed after, so an eject never finds a lingering handle for more than the duration of one response.

```json
  "maps": [
    {"id": "osm-central-america", "display_name": "Offline map: Costa Rica & Central America",
     "display_name_es": "Mapa sin internet: Costa Rica y Centroamérica",
     "url": "/maps/tiles/osm-central-america.pmtiles", "version": "20261015",
```

#### 4.4.3 The viewer (`agent/ui/src/maps/`)
- Libraries, bundled by Vite into the embedded UI, versions pinned in `package-lock.json`: `maplibre-gl` (v5.x), `pmtiles` (v4.x, provides the `pmtiles://` protocol), `@protomaps/basemaps` (v5.x, generates the style layers in JS).
- The style is built at runtime, with **no external URL**:
  ```js
  const origin = window.location.origin;           // http://127.0.0.1:7070
  const style = {
    version: 8,
    glyphs: `${origin}/maps/assets/fonts/{fontstack}/{range}.pbf`,
    sprite: `${origin}/maps/assets/sprites/v4/light`,
    sources: { protomaps: { type: "vector", url: `pmtiles://${origin}${map.url}`,
               attribution: "© OpenStreetMap contributors, Protomaps" } },
    layers: layers("protomaps", namedFlavor("light"), { lang: uiLang })   // "en" | "es"
  };
  ```
  (MapLibre needs absolute URLs for glyphs and sprites, so they're built from `window.location.origin`.)
- **No-network guarantees:** MapLibre's telemetry does not exist in v5, but the build still sets `maplibregl.setRTLTextPlugin` to nothing (the default lazy-loads a URL only if called) and never calls `setWorkerUrl` with a remote URL. The `/maps/` CSP is the full header of [survival-portal.md](survival-portal.md) §4.11 (not the agent's global header of agent.md §3.11.3); it blocks anything else at runtime, and the CI asset scan rejects any `https?://` literal in the bundle except an allowlist (attribution text, `127.0.0.1`).
- **Assets missing:** if `assets.available` is false, the viewer uses the same layers with every `symbol` layer removed (no text, no icons) and shows the banner "Map labels are missing. Names of places can't be shown." / "Faltan las etiquetas del mapa. No se pueden mostrar nombres." (`LAI-SVC-031`). Search still works (results are drawn as plain circles with an HTML label).
- **Several maps:** the map picker lists every map; the default is `maps.default_map`. Only one map is displayed at a time. When the view leaves a map's bounds, the viewer suggests the other map that contains the view, if any.
- UI elements (all large, keyboard reachable): search box, "Where am I", "Nearest: hospital / clinic / water / town" buttons, zoom +/−, a scale bar, a coordinate readout (decimal degrees and DMS) for the map center, and "Copy coordinates".

#### 4.4.4 Offline place search
Feasible offline with GeoNames, so it is in scope (not a limitation).
- **Data:** catalog item `places-central-america` (`kind: maps`, tier 1, source `url`, multiple files `https://download.geonames.org/export/dump/{CR,PA,NI,HN,SV,GT,BZ}.zip`, `version_policy: latest`, `checksum: computed`, `trust: tofu`, `refresh_days: 180`). GeoNames is CC BY 4.0; attribution is shown in the viewer. The fields are defined in [catalog.md](catalog.md) §3 (example item there). A larger `places-north-america` item can exist for the drive.
- **Plausibility check** at sync (in place of a pinned hash): every zip opens, each TSV row has 19 tab-separated columns, ≥ 99 % of rows parse, and the row count is at least 50 % of the previous version's. It is registered as the **content validator** for item `places-central-america` (and any `places-*` item) through the ark-sync `verifying` extension point ([ark-sync.md](ark-sync.md) §4.5); a failed validation is a verify failure → quarantine (`LAI-SYN-020`).
- **Index (in agent memory)**, built at agent start and on `sync.item_done` from the zip files directly (Go `archive/zip`, no extraction to disk), keeping:
  - feature class `P` (populated places) and `A` (`ADM1`, `ADM2`),
  - and these codes: `HSP`, `HSPC`, `HSPD` (hospitals and clinics), `SCH`, `CH`, `PP` (police), `AIRP`, `PRT`, `SPNG`, `WLL`, `RSV`, `LK`, `STM` (water), `MT`, `VLC`, `PK`, `PRK`, `BDG`, `RDJCT`.
  - Fields kept: geonameid, name, asciiname, up to 5 alternate names, lat, lon, feature class/code, country, admin1 name (from `admin1CodesASCII`-free mapping: the ADM1 rows of the same dump), population.
  - Budget: about 300 000 rows and < 60 MB RAM for Central America. The index is lazily built in a goroutine; until ready, search returns `503 {"state":"building"}`.
- **Normalisation:** lowercase, strip accents with a built-in fold table for Latin-1 and Latin Extended-A (`á→a`, `ñ→n`, `ü→u`, …), collapse spaces and punctuation. No `x/text` dependency.
- **Matching and ranking** (`/maps/search?q=`, `q` ≥ 2 chars): candidates = names (and alternates) where the normalised query is a prefix of the name (score 3), a prefix of a word in it (2), or a substring (1). Final score = match score × 10 + kind weight (P with population: `log10(pop+1)`; ADM: 4; hospitals/clinics: 3; others: 1) − `distance_km/100` when `near` is given. Return the top `limit` (≤ 50):
  ```json
  {"results": [{"name": "Hospital San Juan de Dios", "kind": "hospital", "lat": 9.9325, "lon": -84.0889, "admin1": "San José", "country": "CR", "distance_km": 1.2}], "attribution": "GeoNames (CC BY 4.0)"}
  ```
  `kind` is a friendly name from a fixed code→kind table (the UI translates `kind`), first match wins:
  | GeoNames feature | `kind` |
  |---|---|
  | code `HSP` | `hospital` |
  | code `HSPC`, `HSPD` | `clinic` |
  | code `SPNG`, `WLL`, `RSV`, `LK`, `STM` | `water` |
  | code `SCH` | `school` |
  | code `PP` | `police` |
  | code `AIRP` | `airport` |
  | code `MT`, `VLC` | `mountain` |
  | code `PK`, `PRK` | `park` |
  | class `P` with code `PPLC` or `PPLA`, or population ≥ 100 000 | `city` |
  | other class `P` | `town` |
  | anything else | `place` |
- **`/maps/nearest`**: linear scan with an equirectangular approximation over rows of that kind (fast enough at this size: < 20 ms), top 5.
- Missing item → search box disabled with "Place search is not installed." / "La búsqueda de lugares no está instalada." (`LAI-SVC-032`); the map itself still works.

#### 4.4.5 Where am I
The browser Geolocation API is **never** used (offline it fails, and online it sends Wi-Fi data to a network service). Sources, in order:
1. **GPS via gpsd.** If `maps.gps` is `auto` or `gpsd` and something accepts TCP on `127.0.0.1:2947`, the agent connects, sends `?WATCH={"enable":true,"json":true};`, and keeps the last `TPV` report with `mode ≥ 2`.
2. **GPS via NMEA serial.** If `maps.gps` is `nmea:<device>`, or `auto` and a tty under `/sys/class/tty/tty{ACM,USB}*` belongs to a USB device with vendor id `1546` (u-blox) or a product string containing `GPS` or `GNSS`, the agent opens it read-only (`O_RDONLY|O_NOCTTY`, 9600 baud 8N1 via termios for `ttyUSB`; `ttyACM` ignores baud) and parses `$G?RMC` and `$G?GGA` sentences with checksum validation. Other serial devices are never opened by `auto`.
3. **Manual.** The user long-presses or right-clicks the map ("I am here" / "Estoy aquí"), picks a search result, or types coordinates (decimal `9.93, -84.08` or DMS `9°55'48"N 84°4'48"W`). Stored by `PUT /maps/whereami` in `state.json` (`maps.manual_location` = `{"lat","lon","label","set_at"}`, the `maps` sub-tree owned by this spec in [agent.md](agent.md) §3.5), so the desktop and any browser share it.
4. None: the map starts at the default map's center.

`GET /maps/whereami`:
```json
{"source": "gps", "lat": 9.93241, "lon": -84.07912, "accuracy_m": 8, "fix": "3d", "at": "2026-11-02T14:05:11Z", "label": null}
```
`source` ∈ `gps | manual | none`. A GPS fix older than 60 s is reported as `fix: "stale"`. A GPS source configured but silent for 2 minutes raises `LAI-SVC-033` (info, shown only on the map screen). The location never leaves the node (it is not in heartbeats or cloud reports).

### 4.5 Vision

Vision is a normal LLM served by the router. This spec only fixes the requirements:
- The catalog model has `roles` containing `vision`, a `files[kind=mmproj]` entry, and `llama.mmproj_file_kind: mmproj` (catalog.md lint).
- [llama-router.md](llama-router.md) §4.2 writes, for that preset, `mmproj = <absolute path of the mmproj best copy>` and keeps `--mmproj-offload` on (default). If the mmproj has no verified copy, the preset is not generated and the model is `loadable: false` with `LAI-SVC-041`.
- `llama.ctx ≥ 8192` for vision models (images take hundreds to thousands of tokens).
- Clients send images as OpenAI chat content parts:
  ```json
  {"model": "<vision-model-id>", "stream": true, "temperature": 0.2, "max_tokens": 1024,
   "messages": [
     {"role": "system", "content": "<photo system prompt, survival-portal.md §4.7>"},
     {"role": "user", "content": [
       {"type": "text", "text": "What plant is this? Is it safe to eat?"},
       {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,/9j/4AAQ…"}}]}]}
  ```
  Images are resized client-side to at most 1024 px on the long side, JPEG quality 0.85 (≈ 150–400 KB), which bounds image tokens and upload size. The Portal posts this to `/chat/v1/chat/completions` (the key-injecting proxy, [survival-portal.md](survival-portal.md) §4.4).
- **Which model answers a photo:** if a loaded model has the `vision` role, use it. Else, if `models_max` allows another model and it fits ([llama-router.md](llama-router.md) §4.3), load the first vision model of `profile.survival.models` alongside (if that list has no vision model, the first vision model of `profile.include.models`, still subject to the fit rules). Else the Portal asks the user to switch brain (`capabilities.photo.reason: needs_switch`, which carries no doctor code; the Portal, not this spec, maps a "no brain running" state to `LAI-SVC-106`, [survival-portal.md](survival-portal.md) §3.5) (an explicit unload/load, about 20–60 s on ai-n3). No vision model loadable at all → `LAI-SVC-040`, and the Photo button explains it.
- The llama WebUI also accepts image attachments when the selected model has an mmproj, with no extra work from us.

### 4.6 Health checks

The agent's health supervisor (`internal/svc/health`) runs these checks and keeps one state per service. This table is authoritative for the kiwix, whisper, piper and maps checks (intervals, timeouts, URLs); [agent.md](agent.md) §4.3.3 refers here.

| Service | Liveness (every 30 s, 3 s timeout) | Readiness detail | Deep check (on demand: `aictl doctor`, drill) |
|---|---|---|---|
| `llama` | owned by [llama-router.md](llama-router.md) | | |
| `kiwix` | systemd `ActiveState=active` and `GET http://127.0.0.1:8888/library/catalog/v2/entries?count=1` → `200` | `totalResults` equals the number of books in the merged library; mismatch → `degraded` (`LAI-SVC-004`, a ZIM was skipped as invalid) | full-text search in each tier-1 book: `GET /library/search?books.name=<name>&pattern=water&pageLength=1` returns ≥ 1 result |
| `whisper` | `ActiveState=active` and `GET http://127.0.0.1:8081/` → `200` | env model id equals the selected model | transcribe the bundled `drill/en.wav` and `drill/es.wav` (embedded in the agent); word error rate ≤ 30 % |
| `piper` | binary exists and is executable; at least one voice verified | one voice per Portal language (`en`, `es`) | synthesise "Test." / "Prueba." for each default voice: RMS > −40 dBFS, duration 0.3–5 s |
| `maps` | default map BestCopy present and header parses | assets present (the 3 font stacks' `0-255.pbf` and the sprite json); place index ready | fetch one tile at z=10 at the map center through `/maps/tiles/…` with Range and check it starts with the gzip magic `1f 8b` or is a valid MVT |

State values: `ok`, `degraded` (works with a problem), `down` (should run but doesn't respond), `missing_content` (nothing to serve; unit stopped on purpose), `disabled` (turned off in node.yaml), `starting` (first 60 s after a start; failures don't count yet).

**Supervisor rules:**
- 3 consecutive liveness failures of an `active` unit → restart it (`LAI-SVC-050`, info). At most 3 restarts per hour per service; then stop trying, state `down`, raise `LAI-SVC-051` (red in survival mode, yellow otherwise).
- A unit in systemd `failed` state is restarted under the same budget.
- In survival mode, `require_services` from the profile (modes.md §3) that are `down` or `missing_content` are shown in the Portal status strip.

**How the supervisor applies them** (SVC-01, `internal/svc/health`):
- *State.* Per service, in this order: not enabled in `node.yaml` → `disabled` (never probed, never restarted); `Content` says nothing to serve → `missing_content` (never probed, never restarted, with the code the probe names: `LAI-SVC-001`, `010`, `022`, `030`); a unit that is `activating` → `starting`; a unit that is not active (stopped by the operator, or `failed`) → `down` with `LAI-SVC-002` / `011`; active but not probed yet → `starting`; probe passes → `ok`, or `degraded` when the readiness reports a problem of warning or worse; probe fails within 60 s of the unit's start → `starting` and the failure does not count; fails after that → `degraded` for failures 1 and 2, and at the 3rd the unit is restarted (state `starting` again). `down` also is the state of an active unit that fails while the restart budget is spent. A service without a unit (piper, maps) has no restart: its liveness failure is `down` at once, with the code the probe names (`LAI-SVC-020`, `034`).
- *Probes.* Liveness every 30 s, and on every 10 s tick while the service is `starting` and has not answered, so it is `ok` within one tick of answering; each probe call is bounded to 3 s. A unit that just became active (seen through `Manager.Subscribe`) is probed at once. A unit stopped on purpose is never restarted: only `failed` and an active-but-unresponsive unit are.
- *Budget.* A sliding 1-hour window per service, in memory; a restart that fails to run counts too. When it is spent the supervisor does not restart, raises `LAI-SVC-051` (first in `problems`, then the `down` code) and waits: the window frees by itself an hour after the oldest restart, and the supervisor then tries again. `LAI-SVC-050` (info) stays in `problems` while the service has a restart inside the window, and never makes it `degraded`.
- *Events.* `service.state` is published once per change of the health state (a change of the systemd `active`/`sub` alone is not a transition); the first observation after agent start is the baseline and publishes nothing. `code` is the first problem of the new state, only when the new state is not `ok`; `unit` is `null` for piper and maps.
- *Where the Go seams are.* A service plugs in with `health.Spec{Name, Unit, Enabled, Probe, DownCode, Interval}` and a `health.Probe` of four methods (`Liveness`, `Content`, `Readiness`, `Deep`; `health.FuncProbe` fills the ones a service does not need). `health.KiwixSpec` and `health.WhisperSpec` carry the unit and the HTTP liveness of this table; the readiness, content and deep checks of kiwix, whisper, piper and maps are plugged in by SVC-03, SVC-06, SVC-08, SVC-09 and SVC-11. `Supervisor` (an `app.Worker` named `svc-health`) serves `Records` (the rows of `GET /services`, via `api.ServicesDeps.Health`), `Snapshot` (`services.Status` rows for `/status`; `health.Combine(watcher, supervisor)` merges them with llama's), `Reduced` (the cloud heartbeat form), `Flagged` (the survival `require_services` that are `down` or `missing_content`, for the Portal), `Deep`, and the doctor checks `svc.health` (fast, cached) and `svc.deep` (slow, on demand). When the supervisor is wired, `services.Watcher` is limited to llama (`WatcherOptions.Only`) so only one component publishes `service.state` per service.

**Surfaced in:**
- `GET /api/v1/services`:
  ```json
  {"services": [
    {"name": "kiwix", "unit": "localai-kiwix.service", "state": "ok", "since": "2026-11-02T03:00:12Z",
     "last_check": "2026-11-02T14:05:00Z", "detail": "7 books", "books": [{"content_id": "wikimed-en", "name": "mdwiki_en_all", "root": "internal"}], "problems": []},
    {"name": "whisper", "unit": "localai-whisper.service", "state": "ok", "model": "whisper-small", "device": "cpu", "problems": [{"code": "LAI-SVC-013", "severity": "info"}]},
  ```

  `POST /services/{name}/{start|stop|restart}` stays limited to `llama`, `kiwix`, `whisper` (agent.md). `piper` and `maps` have no process to control.
- `GET /api/v1/status` → `services` summary (`name`, `state`, with the unit fields of every row; `unit` is `null` for piper and maps).

## 6. Security considerations

- All three listeners (8888, 8081, and the agent paths) are loopback-only. kiwix-serve and whisper-server have no auth by design (overview.md §3.4). Any local user can reach them; they expose only public content (the library) or a transcription service.
- Units run as `localai` with systemd hardening (§3.3). kiwix-serve gets `PrivateDevices`, `MemoryDenyWriteExecute` and a read-only filesystem view; whisper needs GPU devices so it gets less.
- Piper runs as `localai` with a cleared environment, rlimits, a timeout and a fixed argv. Text goes over stdin, never argv, so there is no injection surface.
- WAV parsing is done in Go with strict bounds; malformed headers can't cause over-reads (fuzz test).
- `--blockexternal` stops Kiwix pages from linking out to the internet; the agent's `/library/` proxy also sets `Content-Security-Policy: default-src 'self' 'unsafe-inline' data:; connect-src 'self'` on proxied HTML, so a ZIM page can't fetch remote resources even online.
- Transcripts, synthesised text and locations are not logged and are never sent to the cloud.
- The GPS reader only opens devices it can identify as GPS, so `auto` never interferes with other serial hardware.
- `PUT /maps/whereami` requires a same-origin `Origin` header (CSRF defence, security-model.md §2).

### 9.2 Integration
- Fake kiwix-serve (records library reloads) + real `kiwix-manage` from the kit in CI (amd64) on two small test ZIMs (the Kiwix test ZIMs, e.g. `wikipedia_en_ray_charles`).

- Maps: headless Chromium (Playwright) opens `/maps/` with every non-`127.0.0.1` request aborted; the test fails if any such request is attempted; the canvas renders; search returns results.

### 9.3 Manual on ai-n3
1. `aictl services` → kiwix, whisper, piper, maps all `ok` (whisper `device: cpu`).
2. `curl -s 'http://127.0.0.1:7070/library/search?books.name=mdwiki_en_all&pattern=bleeding&pageLength=1' | head` → HTML with a result.
3. Record a WAV: `arecord -f S16_LE -r 16000 -c 1 -d 4 /tmp/t.wav` and say "how do I purify water"; then `curl -s -H "Authorization: Bearer $(sudo cat /etc/localai/agent-token)" -F audio=@/tmp/t.wav http://127.0.0.1:7070/api/v1/speech/stt | jq .` → the text, `"language": "en"`.
4. `curl -s -H "Authorization: Bearer …" -H 'Content-Type: application/json' -d '{"text":"Hierva el agua durante un minuto."}' http://127.0.0.1:7070/api/v1/speech/tts -o /tmp/s.wav -D - | grep X-LocalAI` → `X-LocalAI-Language: es`; `aplay /tmp/s.wav` is Spanish speech.
5. Turn Wi-Fi off. Open `http://127.0.0.1:7070/maps/` → the map with labels; search "Liberia" → the Costa Rican city first; "Nearest: hospital" lists hospitals.
6. With a USB GPS (if available) → "Where am I" centres on the fix; without → manual pin persists after reload.
7. Load the vision model and post a photo through the Portal → a description in the UI language.
